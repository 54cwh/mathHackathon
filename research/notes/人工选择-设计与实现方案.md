## 1. 目标与定义

对齐 `genome §10`：**用户无视 fitness 直接指定亲本，形成与自然选择（binary tournament）的直接对照**。
`evolution §5` 原文：候选池与采样规则同上，**仅由「用户替换/指定」**；触发方式、用户接口、回退规则未定义。

## 2. 已存在与缺口

| 层 | 内容 | 状态 |
|---|---|---|
| **L1 繁殖原语** | `breed(A, B, n)`：Parent A × B → n 子代（`genome §4` meiosis/mutation） | **已实现**（api lane）：`POST /v1/breedings`（`api/genomes.py::breed` → `api/genome_lab.py::breed`），**正确复用** `evolution/reproduction.offspring_genome`（无重复实现）。`草案待确认` |

## 3. 方案（L2，evolution 侧）

### 3.1 接口（拟）
`advance_generation(parents, *, experiment_id, generation, seed_manager, config, layout, forced=None)`：

- `forced=None`（默认）：自然选择（现状不变）。
- `forced` 为下列之一（亲本一律以**稳定 `genome_id`** 指定，**禁用下标**）：
  - `forced_pair=(id_a, id_b)`：该一对亲本产**全部 N 子代**（对应「Parent A × B → Breed」；便捷形）。
  - `forced_pairs=((id_a1,id_b1), …, (id_aN,id_bN))`：**逐子代**指定亲本对（长度须 = N；细粒度控制）。
  两者互斥；同时给出即 `ValueError`。

### 3.2 语义与不变量
- 强制通道**跳过** `binary_tournament` 与 `random_pairs`；**不消费 `selection` 命名空间**（选择已由用户决定）。
- 配子/突变**不变**：仍用 `crossover`/`mutation` 的 `t = generation·N + index`（`core §3`），故同 `(config, seed, 亲本)` 下子代**逐位可复现**，且与自然选择同随机流语义。
- 子代 `genome_id` 仍 `mint_id(experiment_id,"genome",generation,index)`（index 0..N−1），`Individual` 初值同 §5.1。

### 3.3 回退规则（须定稿）
1. 指定 id **不在当代** `parents` → `ValueError`。
2. 指定 id 存在但 `viable=False` → `ValueError`（忠实「候选池仅 viable」；不静默放宽）。
3. `forced_pairs` 长度 ≠ N → `ValueError`。
4. `id_a == id_b`（**自交**）→ **允许**并如实记录（用户显式选择；自然配对才禁自体）。
5. `forced` 非空时**不判 `evolution.population_bottleneck`**（用户显式决定；但 forced 自身仍受规则 1/2 约束）。

### 3.4 边界对象（契约改动）
`GenerationResult` 增：
- `selection_mode: "natural" | "artificial"`
- `forced_parent_ids: tuple[str, ...]`（人工=用户给定顺序；自然=空）

`selected_parent_ids` 语义**不变**（本次实际用于繁殖的亲本 id，按子代槽位顺序）。
→ 需回写 `evolution §5.1`；`GenerationResult` 在 `core/核心机制与数据流.md §10` 边界登记，owner 行同步。

## 7. 与自然选择的对照用途（论文/路演）
固定 initial population 与 seed，跑「自然选择 vs 人工选择（同一对亲本持续繁殖）」两臂，比较 allele/phenotype 频率与 fitness 轨迹——即 `genome §10` 的「直接对照」，并可作为 H1/H2 的补充证据。
