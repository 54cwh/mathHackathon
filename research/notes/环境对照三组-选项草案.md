## 1. 背景：为什么这一项现在需要定

### 1.1 现状：默认场景下 8 类事件只有 4 类触发（实测）

复现命令与完整输出见 **附录 A**。结果表：

| 事件（`tests/test_arena.py::KNOWN_EVENTS`，`test_arena.py:10-19`） | 实测次数 | 说明 |
|---|---|---|
| `arena.spawn` | 117 | = 3 seed × 39（12 鱼 + 24 猎物 + 3 天敌），仅 step 0（`env.py:100-101`） |
| `arena.prey_captured` | 28 | 捕食成功（per seed：9 / 9 / 10） |
| `arena.fish_captured` | 2 | 天敌致鱼死亡（per seed：1 / 0 / 1） |
| `arena.episode_end` | 3 | 每 episode 恰一次（`arena实现/§3.2 S21`） |
| `arena.capture_attempt` | **0** | 未出现 |
| `arena.escape` | **0** | 未出现 |
| `arena.collision` | **0** | 未出现 |
| `arena.energy_depleted` | **0** | 未出现 |

条件：`configs/experiment_seeds.yaml` 的正式种子 `[1103, 2207, 3301]`、每 seed 600 步、`ExpertPolicy` 驱动、`ArenaConfig()` 默认值。

### 1.2 三条由既有取值直接推出的可达性结论

以下结论只用 `参数总表` / `config.py` 中**已有**的取值做算术，不含任何新增数值：

1. **`arena.capture_attempt` 在默认配置下不可达。** 该事件的产生条件（`env.py:199-203`）是 `d < capture_radius` **且** `size_ratio = fish.size / prey.size ≤ capture_size_ratio`。以 `growth.initial_size = 1.0`（`config.py:47`）与 `growth.capture_size_ratio = 1.25`（`config.py:49`）计，需 `prey.size ≥ 1.0 / 1.25 = 0.8`；而 `actors.prey_size_max = 0.60`（`config.py:61`），且 `fish.size` 在 `env.py:207-210` 只会增大、不会减小。⇒ 条件恒不成立。实测 20 seed × 600 步内 `fish.size / prey.size` 的最小值为 **1.668**（> 1.25），与之相符（附录 A）。`test_too_small_to_eat_attempt_logged`（`test_arena.py:84-97`）正是靠人工把 `prey.size` 设为 1.5 才触发该分支。
2. **「饿死」在 600 步内不可达（静止鱼也不可达）。** 能量式（`env.py:242-250`）为 `E ← clip(E − base_cost − move_scale·v² + R_food·1[本步捕获], 0, e_max)`。静止（`v = 0`）且不捕食时总耗散 `base_cost_per_step × episode_steps = 0.0008 × 600 = 0.48 < e_max = 1.0`。⇒ 饿死可达的必要条件是 `base_cost_per_step × episode_steps > e_max`，当前不满足。此外 `food_reward = 0.12` 相当于 **150 步**的基础代谢（`0.12 / 0.0008`），单次捕食即可回补。
3. **`arena.collision` 的取值高度依赖 seed。** 在正式种子（1103/2207/3301）上为 0；在 `arena实现/§7 A7` 记录的 5 个 seed（1/7/42/1234/250927）上亦为 0；在本次额外实测的 seed 0–19 中，**19 个 seed 为 0、seed 5 为 220 次**（附录 A）。即：该事件并非结构上不可达，而是「多数 seed 上不出现；一旦出现，则以同一鱼逐步重复计数的方式成簇出现」（与 `arena实现/§3.2 S4`「重叠即每步 +1」的语义一致）。是否把这种「成簇重复」计为一个指标量，属 `认领表/A7` 与 `指标映射草案` G18 的范围，本文件不裁定。

### 1.3 为什么这决定对比实验有没有证据

- `eval/§4:46-53` 的 7 项指标中，**`escape success` 的原始量在正式种子上恒为 0**；`collision` 在正式种子上恒为 0（见 1.2 第 3 条）。
- `赛题`（二）（`docs/赛题补充说明.md:9`）要求形成「原模型 → 修改后模型 → **结果对比**」，改进效果可体现在「准确率、**参数量、推理速度、FLOPs**、小目标识别能力或特殊场景稳定性」等方面。
- `eval/§7:70-83` 的 Experiment F 要求把**相同 initial population** 分别送进三组环境、跑 10–20 generations，并记录 `allele frequency / phenotype frequency / viability / fitness / neuron count / edge count / tau statistics`。`docs/验收清单.md:44` 的 Research 节把 `Environment selection` 列为验收项。
- **推论（描述现状）：** 在「三组环境参数取值未定 + `environment` 不改变任何 Arena 参数」（`api接口/§7.2`，`api接口.md:333`）的当前状态下，Experiment F 的三组环境在代码层面是同一个环境。三组的参数取值因此不是收尾项，而是 Experiment F 是否有可区分信号的前提。

> 上文第 1.2 节的三条是**可达性**陈述，不是指标定义。指标本身的计算口径仍在 `指标映射草案` B1 内登记为未定义（`survival` / `prey capture` / `escape success` / `energy efficiency` 四条的分子分母均未定义）。本文件不替代该文件的裁定。

## 3. S2. 可拉开的维度清单

### S2.0 分类口径（本草案的操作口径，非契约）

清单以 `src/evogenesis/arena/config.py` 的 `ArenaConfig` 叶子字段为准。为使「影响什么」可核对，本节采用一条**可追溯到代码**的分类口径：

- **「改变选择压力」**：该参数的取值进入 `Fish.alive` 的置否路径（`env.py:255-262` 饿死、`env.py:299-314` 被吃），或进入 `metrics.py:1-2` `composite_fitness` 四分量的计量路径（`survival_steps` `env.py:264`、`captures` `env.py:205`、`escape_successes` `env.py:284`、`energy` `env.py:242-250`）。
- **「只改变观测可及性」**：该参数不进入上述两条路径，只决定某事件/计数器是否达到**非退化取值**（即避免 `指标映射草案` 附录 B 所记的「恒 0」），或只改变鱼的感知输入而不直接决定生死。
- **「两者」**：同时满足上述两条。
- 本分类用于排序与排查，**不构成任何契约**；`指标映射草案` B1 已声明各指标的分子分母未定义，故本列只是「该参数会不会动到生死或计量路径」的登记。

> **计数对照（对齐证明见附录 A）：** 本清单条数 = **32** = `arena/config.py` 中 `ArenaConfig` 叶子字段总数。实测输出 `叶子字段总数 = 32`，逐组为 `world 4 / population 4 / sensing 2 / energy 4 / growth 6 / actors 12`。

> 「预期影响哪个指标」一律指向 `eval/§4:46-53` 的指标名（`survival` / `prey capture` / `escape success` / `energy efficiency` / `inference latency` / `parameter count` / `active edges`）与 8 类事件名。指标定义本身未定（`指标映射草案` B1），故本列的措辞为「改变其原始量的可观测性」，不主张指标数值的方向。

| 选项 | 具体机制 | 预期影响 | 代价 / 副作用 |

### S4.B 能量稀缺族 —— 使 `arena.energy_depleted`（饿死）可观测

**机制前提（1.2 第 2 条）：** 饿死可达的必要条件是 `base_cost_per_step × episode_steps > e_max`；当前 `0.0008 × 600 = 0.48 < 1.0`。`food_reward = 0.12` 相当于 150 步基础代谢。
