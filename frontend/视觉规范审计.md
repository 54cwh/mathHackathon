## 2. 逐条裁决（10 条规则）

### 规则 1 —— 整体 3:2 ❌ 未实现 · **前端可 100% 保证**

`App.tsx:14` 是 `h-screen`，**无任何比例约束**。

**几何结论（重要）**：**16:9 (1.778) 比 3:2 (1.5) 更宽** → 在 16:9 显示器上 3:2 内容会被**高度限制**，
于是**左右各留一条 pillarbox 边**，而不是上下留边。这是唯一不违反「不得拉伸成 16:9」的结果。

```css
.eg-frame {
  aspect-ratio: 3 / 2;
  width: min(100%, calc(100dvh * 3 / 2));
  max-height: 100dvh;
  margin-inline: auto;          /* pillarbox 居中 */
}
```

**「允许轻微缩放」应拒绝**：一旦允许，规则 2 的等宽与规则 3 的 5:3 都有了浮动空间 ——
等于把规范交回给浏览器。

### 规则 2 —— 三栏严格等宽 ✅ **已满足**

`App.tsx:41` 的 `lg:grid-cols-3` 编译为 `repeat(3, minmax(0, 1fr))` —— **正是要求的写法**。
当前代码**不存在** 30/30/40、`1fr/1fr/1.5fr`、或「按图片自然宽度」的问题（因为根本没有图）。

**两个真问题**：
1. **`gap-3`（12px）** → 栏间是「边框 + 12px 底 + 边框」，**没有共享分割线**（违反规则 5）；
2. **`grid-cols-1` + `lg:` 断点**（`lg` = 1024px，`tailwind.config.ts` 未覆盖 `screens`）
   → 视口 < 1024px 时**塌成单栏**。宽窗口无碍；**窄窗口 Demo 会直接破规范**。

### 规则 3 —— Arena 5:3 🟡 靠「隐式固有比例」成立，不是契约

`DanioArenaPanel.tsx:11-12,17` 的 `640×384` **恰好 5:3**；`max-h-full max-w-full`（`:214`）
作用在**有固有比例的替换元素**上，会保持比例并 letterbox 在右栏内 → **现在实际是 5:3 的**。

**但它是隐式的**，只在两件事同时成立时才对：
- 位图尺寸不被改（`CANVAS_H` 改成 400 则规则静默失效）；
- CSS 不给 canvas 设显式 `width`/`height`（一旦加 `w-full`，比例交给容器 → 变形）。

**裁决：前端可 100% 保证，但必须从隐式改成显式契约**：
```css
.eg-arena-viewport { aspect-ratio: 5 / 3; width: 100%; }
```

**一个功能性后果（本审计新发现）**：`handleClick`（`:186-193`）用 `getBoundingClientRect()`
做线性映射。**若 canvas 被非等比拉伸，命中测试会系统性偏移** ——
「破坏 5:3」不只是好不好看，**它会直接弄坏点击选鱼**。

**右栏剩余空间**现已用对：`:217-220` 的 session/状态行属「信息区」，符合规则 3 的豁免。

### 规则 4 —— 无圆角 ❌ **4 处 class 违规 + 2 处配置**

| 类型 | 位置 | 现值 |
|---|---|---|
| class | `src/App.tsx:51` | `rounded-md`（主按钮） |
| class | `src/App.tsx:59` | `rounded-md`（Reset） |
| class | `src/components/panel.tsx:15` | `rounded-lg`（每个面板） |
| class | `src/panels/DanioArenaPanel.tsx:214` | `rounded-md`（**竞技场画布**） |
| 配置 | `src/index.css:39` | `--radius: 0.625rem` |
| 配置 | `tailwind.config.ts:48-50` | `lg` / `md: calc(--radius - 2px)` / `sm: calc(--radius - 4px)` |

**无** `rounded-full` / `rounded-xl` 等其它档位（穷尽确认 0 处）。

**统一覆盖位置（回答「在哪里覆盖最合理」）＝ 两处一起改**：
```css
:root { --radius: 0; }
```
```ts
borderRadius: { none: "0", sm: "0", DEFAULT: "0", md: "0", lg: "0", xl: "0", full: "0" },
```
**为什么不能只改 `--radius: 0`**：`md` 会算成 `-2px`、`sm` 会算成 `-4px`。
负 `border-radius` 是**非法值**，浏览器丢弃声明 → 「碰巧没圆角」，但依赖非法 CSS 是脆的。
**必须把 scale 显式写成 0。**

### 规则 5 —— 单一硬分割线 ❌ **比双线更简单也更差**

**穷尽枚举 10 组相邻关系：`border-l` / `border-r` / `border-x` 全库 0 处，
「相邻元素各画相邻方向的边框」这类双线风险点 0 处。**

真实情况：`App.tsx:41` 的 `gap-3` + `panel.tsx:15` 的四边 `border` →
相邻两栏之间是 **「A 右边框 → 12px 背景 → B 左边框」，根本没有共享线**。

**另两处也是「线 + 间距」而非共享线**：`App.tsx:15` header 的 `border-b` 与 `p-3` 之后的面板顶边框；
`App.tsx:47` footer 的 `border-t`。

**推荐的单 owner 写法**：
```tsx
<main className="grid grid-cols-3 divide-x divide-border ...">   {/* 去掉 gap-3 */}
```
`divide-x-*` 只给**除第一个之外**的子元素加 `border-left` —— 一条线、一个 owner、颜色由 `divide-*` 统一。

### 规则 9 —— 像素边缘 🟡 分三层

**（a）前端 100% 可保证（当前已满足，穷尽确认）**：
`shadow*` / `ring-*` / `blur*` / `backdrop-*` / `bg-gradient-*` / `from-to-via-*` / `opacity-*` / `animate-*`
—— **全库 0 处**。唯一命中的是 **`transition-colors` 2 处**（`App.tsx:51,59`）。

**（b）前端能保证、但当前没做（本审计实条）**：
- **`ctx.arc()` / `lineTo()` 画在分数坐标上 → 边缘天然抗锯齿。**
  `DanioArenaPanel.tsx:120,130,137,157-165` 全部画在 `sx()/sy()` 的浮点结果上 →
  **当前竞技场每个圆、每条三角边都是被抗锯齿柔化的**。
  修法：坐标 `Math.round()` + `ctx.imageSmoothingEnabled = false`。
- **全库 0 处 `image-rendering`** → 将来贴精灵图必须加，否则浏览器双线性放大。
- `body { antialiased }`（`index.css:53`）：对**真文字**是对的，对**像素字体**是错的。
  **当前未装像素字体，所以无冲突**；一旦引入点阵字体，必须只在其作用域内关闭。

**（c）前端无法补救（回答直接提问）**：**当前项目里一张这样的图片都没有**
（`public/` 只有 `vite.svg`，`import` 图片 0 处）。
→ **没有需要返工的素材，风险 100% 在「接下来生成什么」。**
判据：PNG 一旦含抗锯齿 / 平滑阴影 / 连续渐变 / 大量插值色，CSS **只能让它更糊，不能变硬**；
唯一出路是重生成，或用调色板量化去逼近。

**（d）附带发现**：`Inter` / `JetBrains Mono` **只声明未加载**（`tailwind.config.ts:52-55`），
浏览器实际回退到 `system-ui` / `ui-monospace` → **任何排版规范目前都不生效**。

### 规则 10 —— Brain Forge 不能像真拓扑 ✅ **应当 100% 前端程序化**

现状：`BrainForgePanel.tsx` 12 行，只有一句中文。**未实现。**

**裁决：SVG / Canvas / CSS + 固定 seed，不用图片。** 四个理由：
1. 规范要的是「像装饰纹理、**但不能被读成拓扑**」—— 这是**否定性约束**，
   而图片模型最不擅长的正是「恰好差一点」；
2. 必须用**调色板里的三种细胞类型色**渲染 → 一旦是图片，颜色就脱离 token 系统，改一次色要重生成一张图；
3. 将来 cell type 数量变化时要跟着变（真数据驱动）；
4. 「**不能数出节点/边**」这件事**代码可以保证**（只画断开小段与粒子簇，永不成图），图片只能祈祷。
