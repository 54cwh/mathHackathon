## 1. 为什么先做通用层

`frontend/交互与可视化.md 附录 A` §1 的穷尽扫描结论：现有 22 个 CSS token、11 个 canvas hex、`README.md` 的 hex 主题表是**三套手写副本**，互不相同。任何「在面板里再写一个 `#60A5FA`」都会让这层腐烂。因此通用层解决三件事：

1. **唯一 owner**：颜色/几何/字体/契约类型/消息通道各只有一处定义；
2. **面板只准引用**：panel 里出现颜色或尺寸字面量即违规；
3. **强制而非自觉**：违规与「生成物漂移」由 `npm run lint:design` **非零退出**拦截（`交互与可视化.md 附录 A §3.5`：「文档是意图，失败测试才是强制」）。

## 3. 依赖铁律与数据流

```text
design/{palette,tokens,geometry,typography}.ts ─┐
                                               ├─► tailwind.config.ts（import 引用）
                                               ├─► src/index.css（npm run gen:design 生成 token 块）
                                               └─► components/*  visuals/*  panels/*  只准 import token

api/types.ts ─► api/arena.ts（REST） ─┐
             └► api/ws.ts（推送）    ─┴─► panels/* ─► store/ui.ts
```

铁律（`lint:design` 与 code review 共同守护）：

1. **单一方向**：`design/` → `components/` → `panels/`；反向 import 禁止。
2. **唯一 owner**：颜色只在 `palette.ts` / `tokens.ts`；几何只在 `geometry.ts`；后端契约类型只在 `api/types.ts`；WS 信封只在 `api/ws.ts`。
3. **面板零样式字面量**：`panels/**` 不得出现 `#hex`/`rgb(`/`hsl(`、Tailwind 命名色阶、`rounded*`/`shadow*`/`blur*`/`gradient`/`transition-colors`（`S1 §3.5`）。
4. **生成物不手写**：`index.css` 的 token 块由 `npm run gen:design` 从 `tokens.ts` 生成；`tailwind.config.ts` 直接 import `design/`。两者的漂移由 `lint:design` 判失败（`S1 §3.4` 双 owner 的根因）。
5. **数值 token 边界**（❌ 工程选择，为免争议而设）：**跨面板或规范规定的**数值（比例、世界/画布尺寸、分割线宽、token）必须在 `design/`；**面板内的局部渲染常量**（如轮询间隔 `POLL_MS`、三角形张角 `2.6`、能量环阈值 `0.3`）留在面板，不进 `design/`。

## 9. 四条架构条款（引自 `S1 §8`）

1. **素材永不承载 UI**——顶栏/底栏/三栏/边框/文字/按钮/占位块一律 DOM。
2. **素材只承载「对象」**——鱼、猎物、捕食者、水草、岩石、瓦片、DNA 纹理。
3. **每个几何约束都有一个 owner 与一个 lint/生成断言**——不靠文档自觉。
4. **`ui_reference_prompts.md` 的三张图是设计参考，不是界面蓝本。**
