`SEED → GENOME → DEVELOP → ARENA → EVOLVE → COMPARE`

- 任意时刻**只有当前段亮**，且**只有一个主按钮「下一步」**推进流程；已完成段可回看，未到段不可跳。
- **AUTO DEMO**：一键按脚本顺序自动跑完六段（可暂停/继续），演示者不必记按钮顺序与调用次序。

- 末段 `COMPARE` 承载赛题要求的「原模型→改后模型→结果对比」（`docs/赛题补充说明.md`）。

**导演线状态机（2026-09-27 定稿；门控在前端，读 `store/ui.ts`）**。「下一步」只在**目标段的门控通过**时可点；点击即 `requestIntent(目标段)`（置 `journey` 并自增 `intent.nonce`），由该段所属面板执行动作——面板用 ref 去重，口径同 `focusNonce`（`通用层接口.md` §7）。

| 段 | 进入门控（前端读 store） | 该段动作（面板执行） | 就绪标志 |
|---|---|---|---|
| `SEED` | 恒真 | 无（起点） | — |
| `GENOME` | 恒真 | 无基因组时 `createGenome`，有则跳过 | `activeGenomeId != null` |
| `DEVELOP` | `activeGenomeId != null` | `develop(with_trace)` → `publishDevelopment` | `development?.result != null` |
| `ARENA` | `development?.result != null` | 确保会话存在并把该个体送入 Arena | `sessionId != null && individuals.length > 0` |
| `EVOLVE` | `sessionId != null && individuals.length > 0` | `POST /v1/sessions/{id}/evolutions/step`（同步约 2s；`evolutionBusy` 显"进行中"） | `generation > 0` |
| `COMPARE` | `generation > 0` | 切到 compare 视图并载入对比表（`GET /v1/comparisons`） | 对比数据就绪 |

- **AUTO DEMO** 定时循环「下一步」；遇到门控未通过即**停在该段并显示提示**（不跳段、不伪造）。

**COMPARE 段（原模型 → 改后模型 → 结果对比；2026-09-27 定稿）**：独立 `compare` 视图，数据来自
`results/tables/*.json`（只读；`api/API接口.md` §2.5）。默认选 `kind="ablation"` 的表，
以「对照臂 × 指标」表 + 主指标柱状图呈现：`composite_fitness` / `capture_rate` / `survival` /
`parameter_count` / `active_edges` / `flops_implemented` / `latency_p50_ms`（对应赛题「补充说明」二
的参数量 / FLOPs / 速度）。**缺失即「未记录」，不补 0**（老 producer 的表可能缺字段）。
- `EVOLVE` 的逐代推进**已落地（2026-09-27）**：Arena 面板内「NEXT GENERATION」按钮 + 导演线进入该段自动推进一代，当代指标就地显示；`COMPARE` 待 P6，AUTO DEMO 目前停在 `COMPARE` 前。

## 4. Brain Forge
动画顺序：

```text
DNA motif
→ q(S)
→ GRN state over 12 development steps
→ precursor division
→ cell differentiation
→ connections appear
→ DanioNet activates
```

所有中间图来自真实模型状态。

**阶段清单（2026-09-27 定稿；全部为真实模型状态）**：

| # | 阶段 | 画面 | 数据（trace 字段） |
|---|---|---|---|
| 1 | `MOTIF → q(G)` | 8 维 motif 亲和度 | `dev_trace.q` |
| 2 | `GRN EXPRESSION`（0..development_steps） | 逐神经元表达强度**逐帧上升** | `expr[i]=mean_d\|g_id\|`（§4） |
| 3 | `DIVISION` | N0 → N0+k 子代出现 | `proliferate` 样本 + `positions` |
| 4 | `FATE` | 六类 fate 着色落定 | `cell_type` + `fate_conf=max_k z_ik`（§6） |
| 5 | `CONNECTOME (p)` | 连接概率场 | `probs`（§8） |
| 6 | `CONNECTOME (A)` | 采样邻接 | `edges` |
| 7 | `DANIONET` | 实时激活 | WS `brain.activation` |

**连接组「两幕真值」（2026-09-27 定稿）**：连接的出现是 `RGCD §8` 的**一步生成**
（\(p=\sigma(\ell)\) 后 \(A\sim\mathrm{Bernoulli}(p)\)），模型里**没有**"逐步长边"这个过程，
故不做任何"逐渐长出"的动画。`connectome` 阶段画两幕：① **概率场 \(p\)**（用 `probs`，按
\(p_{ij}\) 调透明度画候选连接）② **采样结果 \(A\)**（用 `edges`，画真实邻接）。两幕都是模型
真值，可来回切换或自动交替；不含任何伪造的中间态。

### 15.4 已知缺口 / 已标出未做

1. **后端数据缺口（阻塞 `NucleotideStrip` 显示真实数据）**：`/v1/sessions/{id}/snapshot` 响应不含 genotype（`src/api/arena.ts` 的 `ArenaSnapshot` 无 `genotype` / `chromosome` / `sequence`）。故碱基条**在接入后端字段前一直是未初始化态** —— 刻意的，不是遗漏。
2. **`Env` 仍是硬编码字符串** `"Food Rich"`（`components/TopBar.tsx`），**未**由 store 驱动（会话摘要里有 `environment` 字段可接）。改它要动 store 与 Arena 的 `setStats`，属「改现有行为」，故**标出未做**。
3. **DPR 非整数时的像素 + Arena 缩放实测**：两个程序化视觉的位图取**容器 CSS 像素**，DPR 1 / 2 时是整数倍放大（锐利），**DPR = 1.5（本机 Windows 150%）时是 1.5 倍非整数上采样**。Arena 更明显：位图固定 `640×384`，在 1600 宽视口下显示为 `424.89×254.93` CSS px ⇒ 在 DPR 1.5 的设备像素上是 `637×382` ≈ **1:1**（此时最近邻几乎完美）；在 760 宽视口下显示为 `228×137` CSS px ⇒ **0.53 设备像素 / 位图像素**，`auto`（双线性）与 `pixelated`（丢像素）**都会失真**。彻底解决需按 `devicePixelRatio` 与显示尺寸重设位图，属后续项。
4. **`ARENA.hudText` 已删**（`step` 改由 DOM 渲染后无消费者），避免成为审计 §A.3.4 所说的「死 token」。
5. **`DNA.highlight` 已定义但未使用**：标「选定区段」要先有选中态契约（选中的是第几个碱基、映射到螺旋哪一段），该契约未定义；按「未定契约不得被下游依赖」不引入无依据的高亮。
6. **`docs/验收清单.md` 的 Demo 节仍无视觉判据**（池伟豪 lane），故本轮的验收证据只落在本文与 `frontend/README.md`。
7. **注释 / 键名泄漏（本轮新查明，已结构性兜住）**：Tailwind 扫的是**原始文本**（不剥注释），凡与工具类同名的**小写单词**都会被切成候选并生成「没人用」的 CSS —— 三类来源本轮全部实测命中：
   - **TS 属性访问**：`DNA.shadow` → 产出 `.shadow` + `--tw-shadow*`（连带整套 `--tw-ring-*` 基座）；
   - **TS 对象键**：`design/tokens.ts` 的 shell token 键 `ring:` → 产出 `.ring`；
   - **英文注释**：`geometry.ts` 的 "snapped…"（原 "rounded to…"）→ 产出 `.rounded`；`palette.ts` 注释里的 `` `rounded-lg` `` / `` `rounded-full` `` → 产出两个对应类。
   处置：`shadow` 改名 `shade`、注释改写（避免写出那些词）；真正的兜底是 `tailwind.config.ts` 新增的 **`blocklist`**，把「基类 + 常见刻度」**永久禁生成**（实测产物 CSS 由 10.21 kB 降至 9.50 kB）。静态检查抓不到这类（它剥注释、且不把属性访问当类名），所以必须靠 `blocklist` —— 这条经验写进了 `palette.ts` 的注释。
8. **`--tw-ring-*` / `--tw-backdrop-*` 基座仍在产物里**（12 + 19 条声明）：它们位于 Tailwind 的通用 `*,::before,::after{…}` 基座，**无类选择器、无元素可匹配** ⇒ 惰性、不影响渲染；`.ring` **类本身已不再生成**。要连这段基座一起去掉需进一步关闭 `ringWidth` / `backdropBlur` 等 core plugins —— 那会动 `tailwind.config.ts` 的插件层，属可选项，本轮**标出未做**。

10. **Arena 画布的 `image-rendering` 仍是 `auto`**（两个程序化视觉已加 `.pixelated`）：`DanioArenaPanel` 的 `imageSmoothingEnabled = false` 只管**位图内部**绘制，不管**画布→屏幕**缩放。按 §十三「不为视觉重写 Arena」**未擅改**，实测数据见第 3 条。

### 规则 1 —— 整体 3:2 ❌ 未实现 · **前端可 100% 保证**

## A.6. 方案 A / B / C 裁决

**→ C。三条硬理由：**

1. **A 会让规范不可实现。** 你把「3:2 / 三栏等宽 / 5:3 / 无圆角 / 1–2px 共享线 / 无数字」放在同一张图上 ——
   而我们已经用四轮提示词迭代证明**图片模型无法稳定命中其中任何一条**
   （它不认 16:9、不收圆角、把 5:3 画成高瘦、照画数字）。
2. **B（底图 + DOM 覆盖）是陷阱。** 它留下一个**必须持续对齐**的契约：DOM 的文字/按钮必须永远
   压在图里烘焙的**同名元素**上。图中每个标签的位置、字号、字色都成了**隐式像素级依赖** ——
   而**图的每一次重生成都会破坏它**。你付了 A 的成本，只拿到 C 的一半。
3. **C 已是现状。** `public/` 只有 `vite.svg`，外壳全是 DOM。**你不需要迁移，你需要补齐 + 推平。**

**唯一需要改变的只是定位**：`ui_reference_prompts.md` 的三张图**不是界面蓝本**，而是
（a）调色板来源、（b）密度与质感的上限参考、（c）「哪些地方像素、哪些地方精密」这条边界的示意。
这一点**文档里已经写了**（`ui_reference_prompts.md:151-152`、`artifacts/assets_placeholder/README.md:37-38`），
但**从未被写成架构条款**。
