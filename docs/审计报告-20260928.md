## 2. 阻断级（1 项）

### B1. 配置漂移：actors 节缺 2 键 → 唯一失败的测试 + 参数总表漏登

**现象**：tests/test_config_schema.py::test_default_arena_section_keys_match_module_schema 失败（全套 709 个测试中唯一红灯）。

**证据链**（逐点核实）：

| 位置 | fish_speed_scale | fish_speed_cap |
|---|---|---|
| src/evogenesis/arena/config.py:97-98（dataclass，权威 schema） | 有，默认 1.0 | 有，默认 1.0 |
| src/evogenesis/arena/env.py:341（消费点） | np.clip(v * scale, 0, cap) | 同左 |
| configs/demo_arena.yaml:49-50 | 1.0 | **0.50** |
| configs/default_arena.yaml 的 actors: 节（17 键） | **缺失** | **缺失** |
| docs/参数总表.json（154 条） | **未登记** | **未登记** |

**后果**（四条独立红线同时受损）：

1. **提交门禁红灯**：违反 AGENTS.md「提交前须通过 make lint && make test」与「审查：自动检查全绿」留痕要求。
2. **镜像声明失真**：core/核心机制与数据流.md §0 明文「load_arena_config 的 dataclass 默认即 configs/default_arena.yaml 的冻结镜像」——现在 dataclass 比 YAML 多 2 键，镜像不再成立。
3. **实质行为差异**：正式实验（走 default_arena.yaml，缺键回落 dataclass 默认 cap=1.0）与 Demo（cap=0.50）的鱼速上限**相差 2 倍**。若 0.50 是 play-test 调优结果而未回灌正式实验配置，则基线/消融实验（Experiment C/D）与 Demo 展示的行为**不在同一参数域**，影响论文口径一致性。
4. **参数总表漏登**：违反「参数依据与状态的唯一来源是参数总表」——出现在 config 或 dataclass 的运行期取值都必须登记。

**修复方案（需用户裁决权威值，二选一）**：

- **方案 A（cap=0.50 为权威）**：若 0.50 是 play-test 后的调优值 → default_arena.yaml 补 fish_speed_scale: 1.0、fish_speed_cap: 0.50，参数总表登记（依据标「play-test 设计选择 D」或按实际依据），并评估已跑实验是否需重跑。
- **方案 B（cap=1.0 为权威，Demo 特调）**：default_arena.yaml 补 1.0 / 1.0，demo_arena.yaml 保持 0.50，但须在参数总表单独登记 demo 覆盖值的依据，并在演示讲稿 / 论文 Demo 节注明「演示鱼速经调优，与实验配置不同」。

两方案修复后测试自动转绿；同时须核对 arena/Danio_Arena设计与实现说明.md §18 是否有对应词表 / 参数条目需同步。

### 4.5 测试套件的 Windows 编码告警

pytest 运行中出现的 UnicodeDecodeError（gbk codec，subprocess 读线程）来自测试内子进程输出按 GBK 解码。不影响结果判定，但在现场机（中文 Windows 默认 GBK 代码页）上同类问题可能干扰长跑实验的日志管道；建议后续统一在测试 / 脚本子进程调用处显式 encoding='utf-8', errors='replace'。
