# 核心机制（core/）

> **管辖范围**：数据管线、模块边界清单、seed/ID/存储与 §0/§4/§5/§7 机制契约。不拥有：模块内算法、**参数取值**（归 `configs/` + `docs/参数总表.json`）。（层级与归属见 `AGENTS.md`「文档层级与优先级」。）

`src/evogenesis/core/` 是方向无关的机制底座，被所有任务包依赖，提供：`config`（配置加载）、`seed`（种子统一派生）、`ids`（稳定 ID 铸造）、`tensors`（NumPy→torch 转换）、`logging`、`tracking`、`registry`、`io`。所有随机过程由本模块的 seed manager 统一派生（Python `random` / NumPy / PyTorch CPU / PyTorch CUDA）。

本文件下半部分同时是**数据全流程规范**：回答"数据从哪里来、到哪里去、每个数字如何可复现"。

## 0. core 模块与契约边界

| 模块 | 职责 | 契约状态 |
|---|---|---|
| `config` | 加载并校验 `configs/*.yaml`，向各包暴露参数 | **已定**：PyYAML 解析 + Pydantic v2 类型校验；env 层沿用 pydantic-settings 约定（`EVOGENESIS_` 前缀、`__` 嵌套）——**仅命名约定**，值按 YAML 标量解析（`configs/` 与 env 用同一套标量语法，JSON 为 YAML 的子集），**在 `core/config.py` 内做四层深合并**（`CLI > env > file > default`）；因 pydantic-settings 的 settings source 是整字段替换、不支持 section 深合并，未采用其解析机制；跨语言字段与 `schemas/` 对齐 |

## 1. 数据哲学：仿真自生成，不依赖外部训练数据

本项目**不使用任何外部数据集进行训练**。所有数据由受控仿真生成。

**为什么采用这一模式：**

1. **研究对象是生成系统本身。** 待检验的命题链——不同 DNA ⇒ 不同架构 ⇒ 不同行为 ⇒ 不同环境不同演化结局——本质是受控对照实验：只有仿真可以做到"只改一个碱基、其余全同"。外部观测数据无法回答这些问题。
2. **领域惯例。** 神经演化 / artificial life / 演化机器人的经典工作（NEAT、HyperNEAT 等）均采用"仿真自生成 + 种子可复现"的数据模式。
3. **数据不是"编的"，是受控实验产生的。** 每个数字都能由 `(config, master seed)` 在固定环境下重放，满足本课题的对照实验需求（不宣称在所有意义上强于观测数据）。

**严谨性配置（继承自冻结文档，不可削减）：** 正式实验固定 3 个随机种子（`formal_seeds = 3`）；baseline / ablation 对照；Mendel Mode 数值验证；Demo 固定种子离线可复现。

## 2. 数据流水线总览

```text
configs/*.yaml (含 seed)
      │
      ▼
Seed Manager（core §3：master seed 派生一切）
      │
      ▼
genome ──► development ──► connectome ──► Arena 仿真（20 Hz × 600 steps / episode）
(DNA+motif)  (GRN/RGCD 发育)  (DanioNet 48-node)
                     ├──► 专家轨迹（ExpertPolicy）──► BC 训练 ──► ΔW（当代，不遗传）
                     ├──► 事件日志（event log）──────► 实验指标
                     └──► 帧快照（位置/朝向/能量）──► WS 实时推送（仅演示，不落盘）
      │
      ▼
fitness ──► selection/drift ──► 下一代 genome（回到 genome）
      │
      ▼
results/runs/<experiment_id>/   （不入库；目录布局见 experiment/实验与评价体系.md §11）
      │
      ▼  仅 Demo 所需子集
artifacts/               （入库：固定 seed、Demo 种群、小 checkpoint）
```

关键原则：**磁盘事件日志是 WS 推送的超集（单向同源）**。推送的每个事件都能在落盘日志中找到；日志中存在仅记录、不推送的事件（如 48×48 连接矩阵）。两路共用同一 `(experiment_id, episode_id, seq)` 生成器，保证可对齐。

## 3. 种子体系（可复现性的根）

本节的派生式为本模块所有（唯一实现 `core/seed.py`）：

| 项 | 约定 |
|---|---|
| 统一设置的随机源 | Python `random`、NumPy、PyTorch CPU、PyTorch CUDA |
| 派生关系 | mutation / crossover / development / Arena spawn 的子种子全部由 master seed 派生 |
| 正式实验 | `formal_seeds = 3`（`configs/experiment_seeds.yaml`），三个种子独立成表 |
| 现场 Demo | `configs/demo_seed.yaml` 单独固定，与实验种子隔离 |
| 复现判据 | 同一 `(config 文件, master seed)` 在**同设备、同线程数**下结果一致；跨设备只要求统计等价（浮点归约非确定性），对应验收清单"同一 genome + seed 产生同一 developmental trace"） |

**派生函数（定稿）**：子种子用 NumPy `SeedSequence`，定义如下（每个符号给出定义 / 形状 / dtype / 值域）：

| 符号 | 定义 | 形状 | dtype | 值域 |
|---|---|---|---|---|
| `master_seed` | 实验/Demo 主种子（`configs/demo_seed.yaml`、`experiment_seeds.yaml`） | 标量 | `int` | `[0, 2**32)` |
| `ns` | 命名空间 id，注册表 `mutation=0, crossover=1, development=2, arena_spawn=3, motif_catalog=4, network_init=5, selection=6`；全局唯一、不回收 | 标量 | `int` | `[0, 2**32)` |
| `S_ns` | 命名空间序列 `SeedSequence([ns, master_seed])` | 标量对象 | — | — |
| `t` | 实体在命名空间内的**稳定序号** | 标量 | `int` | `≥ 0` |
| `C(ns, t)` | 实体子种子 `S_ns.spawn(k)[t]` | 标量对象 | — | — |
| `g` | 子种子派生的整数种子 `C.generate_state(1, dtype=uint32)[0]` | `(1,)` | `uint32` | `[0, 2**32)` |

- **变化 ID 前置**：列表熵写作 `[ns, master_seed]`（`ns` 在前）。依据 NumPy《Parallel RNG》"place the varying IDs *before* the unvarying root seed"，且本体系在列表熵之上**再 `spawn`** 实体子序列，前置可避免列表熵与 spawn 路径碰撞（出处 `research/reference/design-basis-reproducibility.md`）。
- **实体序号语义**：`t` 必须由**稳定 ID**（`fish_id` / `genome_id` / `generation` / episode 序号等）确定性映射，**不得使用调用顺序**；要求 `k > t`。实现按需 `spawn` 并按命名空间缓存、只增不减（NumPy 保证 `spawn` 前缀稳定，结果与 `k` 取值无关）。
- **配子级 `t`（定稿，2026-09-26）**：`crossover` / `mutation` 命名空间的实体是**子代配子**，其 `t = generation · N + index`（`N` = 每代出生数 `population_size`；`generation` / `index` 取自该子代 `genome_id` 的 `…:g<generation>:genome<index:04d>`）。`t` 由 `genome_id` 确定性解析、不使用调用顺序，且**全局唯一**——跨代同一出生槽位（同 `index`）不再复用同一随机流。`selection` 命名空间的实体是「一次世代繁殖」，其 `t` 取**子代世代号 `generation`**（`evolution §5`）。
- **四路随机源**由同一 `C` 派生：NumPy `default_rng(C)`；Python `random.Random(int(g))`；PyTorch `torch.Generator(device).manual_seed(int(g))`。
- **PyTorch 组合的验证要求**：「NumPy 子种子 → torch 种子」的组合无官方出处，属**项目选定**，须最小复现验证「同 `master_seed` 两次独立进程产同一 torch 序列」（`tests/test_seed.py::test_torch_generator_cross_process_deterministic`）。

### 3.1 稳定 ID（owner: core）

`fish_id` / `genome_id` / `generation` / `experiment_id` / `environment_id` 的**格式、派生与唯一性域**归本模块（实现 `core/ids.py`）；`api/API与系统工程.md` §3 仅列名，以本节为准。

| ID | 类型 / 格式 | 派生 | 唯一性域 |
|---|---|---|---|
| `experiment_id` | `str`，非空、不含 `:`，形如 `exp-0001` | 由编排层给定，本模块不铸造 | 全局 |
| `generation` | `int`（≥ 0） | 演化代数，亲本代 +1 | 单个 experiment |
| `genome_id` | `str`，`<experiment_id>:g<generation>:genome<index:04d>` | `mint_id(experiment_id, "genome", generation, index)` | 单个 experiment |
| `fish_id` | `str`，`<experiment_id>:g<generation>:fish<index:04d>` | `mint_id(experiment_id, "fish", generation, index)` | 单个 experiment |
| `environment_id` | `str`（非空） | 由实验对照配置给定（`experiment/实验与评价体系.md`），本模块不铸造 | 单个 experiment |

- `index`：`int`，值域 `≥ 0`，为该代内稳定序号（枚举赋值，写入后不得重排；不代表数组下标语义）；格式串中 `04d` 为最小补零宽度（`≥ 10000` 不截断）。
- `mint_id` 为纯函数、确定性：同一 `(experiment_id, role, generation, index)` 恒得同一结果。
- **非空约束**：`genome_id` / `fish_id` 一律非空（`schemas/genome.schema.json`、`schemas/fish.schema.json` 加 `minLength: 1`；序列化边界 `DiploidGenome.to_dict()` 对空 `genome_id` 报错）。
- §3 的实体序号 `t` 由上述稳定 ID 确定性映射，禁止调用顺序。

## 4. 训练数据：ExpertPolicy 轨迹（BC Stage 1）

唯一的"训练"环节是行为克隆（`connectome/DanioNet设计规范.md` §6），其数据流如下。

### 4.1 生成方式

- **教师**：透明 ExpertPolicy——手写规则控制器（视野内追踪最近猎物、检测到威胁时逃离），可解释、可写进论文。
- **采集**：ExpertPolicy 在 Arena 正常 episode（30 s / 600 steps）中驱动鱼，逐 step 记录样本。

### 4.2 样本记录字段（与冻结参数严格对齐）

| 字段 | 类型 / 维度 | 说明 |
|---|---|---|
| `schema_version` | str | 轨迹 schema 版本；字段/词表变更须递增 |
| `experiment_id` | str | 稳定 ID（AGENTS「稳定 ID」），用于 join 回 run |
| `episode_id` | str | 稳定 ID，形如 `ep0001` |
| `environment_id` | str | 环境对照组（见 §6） |
| `generation` | int | 演化代数 |
| `fish_id` / `genome_id` | str（稳定 ID，见 core §3.1） | 禁止用数组下标当 identity |
| `step` | int | 0–599 |
| `observation` | float[**12**]（`sensory_dim = 12`） | 感知向量，**维度顺序冻结**（维度定义见 `connectome/DanioNet设计规范.md` §2；验收清单硬性要求） |
| `expert_action` | float[**2**]（`action_dim = 2`） | `(ω*, v*)` 转向角速度 + 推进 |

**episode header（JSONL 首行 `record_type=header`）**：`episode_seed / total_steps / terminated / truncated`（可选 `environment_config / obs_dim_names`）。

> 本表已定稿，字段与 `schemas/trajectory.schema.json` 一致（决策见 `research/notes/契约决策记录.md`）。

### 4.3 训练预算与损失（公平性红线）

- 训练契约（预算、采样与标准化、损失与权重、优化器）的**单一 owner** 是 `learning/行为克隆学习.md` §3，本文件不重复定义其数值。
- **公平性红线（本文件声明）**：基线 / 消融实验必须满足相同数据、相同训练预算、相同标准化口径、参数量同一数量级、相同 evaluation episodes（实验侧控制见 `experiment/实验与评价体系.md` §4）。

### 4.4 遗传边界（论文核心卖点，不可破坏）

训练产生的 \(\Delta W\) **不遗传**。后代只继承 DNA，从发育重新开始。BC 只影响当代个体表现型，绝不进入繁殖通路。

### 4.5 存放

- 位置：`results/runs/<experiment_id>/trajectories/`（**不入库**，随 run 归档）。
- 命名：逐 episode 一文件，`episode_<episode_id>.jsonl`（如 `episode_ep0001.jsonl`）。
- 格式：JSONL（与事件日志同格式）；如需列式分析可另导 Parquet，但以 JSONL 为准。字段见 §4.2。
- 契约：`schemas/trajectory.schema.json`（已定稿，与 §4.2 字段一致；JSONL 首行 header + 逐步 step）。

## 5. Arena 运行时数据：事件日志

事件日志是 Arena 的验收硬项（docs/验收清单.md Arena 节），也是全部实验指标的原始来源。

### 5.1 事件类型（设计参考；权威词表见 arena）

> **权威说明**：机器可读的事件词表以 `arena/Danio_Arena设计与实现说明.md` §18 实现映射中的事件词表 + `tests/test_arena.py::KNOWN_EVENTS`（v1，已生效）为准；本表是设计侧参考。命名 `arena.<event>`，只增不删。

每条事件记录携带公共字段：`schema_version / experiment_id / episode_id / environment_id / generation / step / seq`，事件专属载荷见下表。

| 事件 | 载荷要点 |
|---|---|
| `spawn` | fish/prey/predator/obstacle 初始位置、尺寸 |
| `prey_captured` | 捕食者 fish_id、prey_id、能量增量（`food_reward`） |
| `escape` | 威胁源、反应时延 |
| `energy_depleted` | fish_id、存活步数（= 死亡判定） |
| `capture_attempt` | 距离、尺寸比（对照 `capture_size_ratio` 阈值；该值在 `docs/参数总表.json` 中为 `proposed_change`，未定稿前不作契约） |

### 5.2 与 API 的关系

- 实时演示经 WS `/v1/ws` 推送（信封 `{v, type, seq, ts, payload}`）；快照走 `GET /v1/sessions/{session_id}/snapshot`。

## 6. 实验数据：记录什么

全部按 `experiment/实验与评价体系.md` 执行，此处只列数据产出清单。

**序列化与数值约定：**

- 数组落盘统一 `float32`（与 PyTorch 默认一致），禁止隐式提升为 `float64`；CPU / GPU dtype 必须一致。
- **内存/训练 dtype**：模型张量与梯度统一 `torch.float32`；禁止全局 `set_default_dtype(torch.float64)`；跨框架边界显式转换（NumPy 默认 `float64`，`torch.from_numpy` 会得到 `float64`）。CPU / GPU **不承诺逐位一致**，比较用容差并注明设备（呼应 §9 复现性）。
- **跨框架边界转换（定稿）**：NumPy `float32` → `torch.float32` 的转换由**消费方**在其入口调用 `core/tensors.py::to_float32_tensor`（`dtype` 固定 `torch.float32`；输入任意 dtype 一律经 `np.asarray(..., dtype=float32)` 归一；`device` 可选，缺省留在当前默认设备，需要固定设备时由调用方显式传入）完成，**producer 不引入 torch 依赖**。如 `genome` 产出 `q(G)`/`E_A,E_B` 为 NumPy `float32`，进入 `development` 前由 development 入口转换（见 `development/RGCD数学模型.md` §1）。
- 表格用 CSV（UTF-8、逗号分隔）；时间戳用 ISO-8601；JSONL 每行一个 UTF-8 对象。
- `metrics.csv`、`population.jsonl` 采用与 `experiment/实验与评价体系.md` §11 一致的字段。

## 8. 外部公开数据的使用政策

**原则：外部数据不用于训练，只用于两类用途——(a) 设计依据的文献引用；(b) 生物学合理性校验（报告可选小节，非必需）。**
