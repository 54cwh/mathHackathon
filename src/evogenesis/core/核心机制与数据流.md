# 核心机制（core/）

`src/evogenesis/core/` 是方向无关的机制底座，被所有任务包依赖，提供：`config`（配置加载）、`seed`（种子统一派生）、`logging`、`tracking`、`registry`、`io`。所有随机过程由本模块的 seed manager 统一派生（Python `random` / NumPy / PyTorch CPU / PyTorch CUDA）。

本文件下半部分同时是**数据全流程规范**：回答"数据从哪里来、到哪里去、每个数字如何可复现"。

## 0. core 模块与契约边界

| 模块 | 职责 | 契约状态 |
|---|---|---|
| `config` | 加载并校验 `configs/*.yaml`，向各包暴露参数 | **已定**：Hydra/OmegaConf 合成 + Pydantic 类型校验 + JSON Schema；覆盖优先级 `CLI > file > default`（env 层无单一权威原文，标 `草案待确认`） |
| `seed` | master seed → 各随机过程子种子 | **已定稿**：NumPy `SeedSequence` 命名空间派生（见 §3） |
| `logging` | 运行日志 | **已定稿**：structlog JSON，字段对齐 OpenTelemetry Logs |
| `tracking` | 实验跟踪与产物登记 | **已定稿**：字段对齐 MLflow（本地 file store，现场离线） |
| `registry` | 稳定 ID → 对象注册与查询 | **已定稿**：稳定名 + 不可变版本 + alias；本地 JSON 索引 |
| `io` | 序列化读写 | **已定稿**：JSONL/CSV/Parquet；数组 float32（§7） |

> 依据与出处：`research/reference/design-basis-infra.md`、`design-basis-reproducibility.md`。仍未定项见 §10。

## 1. 数据哲学：仿真自生成，不依赖外部训练数据

本项目**不使用任何外部数据集进行训练**。所有数据由受控仿真生成。

**为什么采用这一模式：**

1. **研究对象是生成系统本身。** 待检验的命题链——不同 DNA ⇒ 不同架构 ⇒ 不同行为 ⇒ 不同环境不同演化结局——本质是受控对照实验：只有仿真可以做到"只改一个碱基、其余全同"。外部观测数据无法回答这些问题。
2. **领域惯例。** 神经演化 / artificial life / 演化机器人的经典工作（NEAT、HyperNEAT 等）均采用"仿真自生成 + 种子可复现"的数据模式。
3. **数据不是"编的"，是受控实验产生的。** 每个数字都能由 `(config, master seed)` 在固定环境下重放，满足本课题的对照实验需求（不宣称在所有意义上强于观测数据）。

**严谨性配置（继承自冻结文档，不可削减）：** 正式实验固定 3 个随机种子（`formal_seeds = 3`）；baseline / ablation 对照；Mendel Mode 数值验证；Demo 固定种子离线可复现。

## 2. 数据流水线总览

```text
configs/*.yaml (含 seed)
      │
      ▼
Seed Manager（api/API与系统工程.md §6：master seed 派生一切）
      │
      ▼
genome ──► development ──► connectome ──► Arena 仿真（20 Hz × 600 steps / episode）
(DNA+motif)  (GRN/RGCD 发育)  (DanioNet 48-node)
                     ├──► 专家轨迹（ExpertPolicy）──► BC 训练 ──► ΔW（当代，不遗传）
                     ├──► 事件日志（event log）──────► 实验指标
                     └──► 帧快照（位置/朝向/能量）──► WS 实时推送（仅演示，不落盘）
      │
      ▼
fitness ──► selection/drift ──► 下一代 genome（回到 genome）
      │
      ▼
results/runs/<experiment_id>/   （不入库；目录布局见 experiment/实验与评价体系.md §11）
      │
      ▼  仅 Demo 所需子集
artifacts/               （入库：固定 seed、Demo 种群、小 checkpoint）
```

关键原则：**磁盘事件日志是 WS 推送的超集（单向同源）**。推送的每个事件都能在落盘日志中找到；日志中存在仅记录、不推送的事件（如 48×48 连接矩阵）。两路共用同一 `(experiment_id, episode_id, seq)` 生成器，保证可对齐。

## 3. 种子体系（可复现性的根）

遵循 `api/API与系统工程.md` §6 Seed Manager：

| 项 | 约定 |
|---|---|
| 统一设置的随机源 | Python `random`、NumPy、PyTorch CPU、PyTorch CUDA |
| 派生关系 | mutation / crossover / development / Arena spawn 的子种子全部由 master seed 派生 |
| 正式实验 | `formal_seeds = 3`（`configs/experiment_seeds.yaml`），三个种子独立成表 |
| 现场 Demo | `configs/demo_seed.yaml` 单独固定，与实验种子隔离 |
| 复现判据 | 同一 `(config 文件, master seed)` 在**同设备、同线程数**下结果一致；跨设备只要求统计等价（浮点归约非确定性），对应验收清单"同一 genome + seed 产生同一 developmental trace"） |

**派生函数（定稿）**：子种子用 NumPy `SeedSequence`——命名空间法 `SeedSequence([master, namespace_id])`（如 `mutation=0, crossover=1, development=2, arena_spawn=3`），或等价的 `SeedSequence(master).spawn(k)[i]`。出处：`research/reference/design-basis-reproducibility.md`。

## 4. 训练数据：ExpertPolicy 轨迹（BC Stage 1）

唯一的"训练"环节是行为克隆（`connectome/DanioNet设计规范.md` §6），其数据流如下。

### 4.1 生成方式

- **教师**：透明 ExpertPolicy——手写规则控制器（视野内追踪最近猎物、检测到威胁时逃离），可解释、可写进论文。
- **采集**：ExpertPolicy 在 Arena 正常 episode（30 s / 600 steps）中驱动鱼，逐 step 记录样本。

### 4.2 样本记录字段（与冻结参数严格对齐）

| 字段 | 类型 / 维度 | 说明 |
|---|---|---|
| `schema_version` | str | 轨迹 schema 版本；字段/词表变更须递增 |
| `experiment_id` | str | 稳定 ID（AGENTS「稳定 ID」），用于 join 回 run |
| `episode_id` | str | 稳定 ID，形如 `ep0001` |
| `environment_id` | str | 环境对照组（见 §6） |
| `generation_id` | int | 演化代数 |
| `fish_id` / `genome_id` | str（稳定 ID，见 api/API与系统工程.md §3） | 禁止用数组下标当 identity |
| `step` | int | 0–599 |
| `observation` | float[**12**]（`sensory_dim = 12`） | 感知向量，**维度顺序冻结**（维度定义见 `connectome/DanioNet设计规范.md` §2；验收清单硬性要求） |
| `expert_action` | float[**2**]（`action_dim = 2`） | `(ω*, v*)` 转向角速度 + 推进 |

> ⚠️ 本表为**草案**（见 §10 待冻结项 #1）：schema 未冻结前，实现侧不得自行增删字段。

### 4.3 训练预算与损失（公平性红线）

- 每条 viable DanioNet 相同预算：`bc_updates = 20` 次 mini-batch 更新（`K = 20`）。
- 损失：

\[
\mathcal{L} = \lambda_\omega \, MSE(\hat\omega, \omega^*) + \lambda_v \, MSE(\hat v, v^*)
\]

- ⚠️ **未定项**：\(\lambda_\omega, \lambda_v\) 的具体取值**尚未定义**（`docs/参数总表.json` 已登记为 `missing`）。在回写参数表并定稿前，实现侧**不得自行选定**，正式实验中也不得作为既定契约使用。
- 基线 / 消融实验必须满足：相同数据、相同训练预算、参数量同一数量级、相同 evaluation episodes（`experiment/实验与评价体系.md` §4 控制）。

### 4.4 遗传边界（论文核心卖点，不可破坏）

训练产生的 \(\Delta W\) **不遗传**。后代只继承 DNA，从发育重新开始。BC 只影响当代个体表现型，绝不进入繁殖通路。

### 4.5 存放

- 位置：`results/runs/<experiment_id>/trajectories/`（**不入库**，随 run 归档）。
- 命名：逐 episode 一文件，`episode_<episode_id>.jsonl`（如 `episode_ep0001.jsonl`）。
- 格式：JSONL（与事件日志同格式）；如需列式分析可另导 Parquet，但以 JSONL 为准。字段见 §4.2。
- ⚠️ 对应的 `schemas/trajectory.schema.json` **尚未冻结**——按 `api/API与系统工程.md` §10「schema/config 变更必须双方同步」，字段定稿前需池伟豪确认。字段草案即 §4.2 表格。

## 5. Arena 运行时数据：事件日志

事件日志是 Arena 的验收硬项（docs/验收清单.md Arena 节），也是全部实验指标的原始来源。

### 5.1 事件类型（草案，待冻结）

每条事件记录携带公共字段：`schema_version / experiment_id / episode_id / environment_id / generation_id / step / seq`，事件专属载荷见下表。

| 事件 | 载荷要点 |
|---|---|
| `spawn` | fish/prey/predator/obstacle 初始位置、尺寸 |
| `prey_captured` | 捕食者 fish_id、prey_id、能量增量（`food_reward`） |
| `escape` | 威胁源、反应时延 |
| `energy_depleted` | fish_id、存活步数（= 死亡判定） |
| `capture_attempt` | 距离、尺寸比（对照 `capture_size_ratio` 阈值；该值在 `docs/参数总表.json` 中为 `proposed_change`，未定稿前不作契约） |
| `episode_end` | 存活列表、最终能量、fitness |

命名风格与 WS 消息 `type` 的点分层约定（R11）保持一致，磁盘与推送共用同一词表。

### 5.2 与 API 的关系

- 实时演示经 WS `/v1/ws` 推送（信封 `{v, type, seq, ts, payload}`）；快照走 `GET /v1/sessions/{session_id}/snapshot`。
- **不每帧发送 48×48 连接矩阵**（api/API与系统工程.md §5）；矩阵只存在于发育产物与落盘记录中。

## 6. 实验数据：记录什么

全部按 `experiment/实验与评价体系.md` 执行，此处只列数据产出清单。

| 实验 | 数据产出 |
|---|---|
| A — Genome → Architecture | motif affinity、GRN 终态、neuron count、cell-type 分布、edge density、τ 分布 |
| B — Single-base Mutation | 代表性 haplotype 全部 256 个碱基位点（haploid，2×128 bp）的确定性替换扫描结果 |
| 演化 | 10–20 代；每代记录 allele frequency、phenotype frequency、viability、fitness、neuron count、edge count、τ 统计量 |
| Mendel 验证 | 160 个 offspring（AaBb × AaBb）经验比例 vs 9:3:3:1 |
| BC 训练 | 每条 DanioNet 的 loss 曲线与模仿误差（held-out 专家样本上的 MSE(ω) + MSE(v)） |
| 基线/消融 | 指标：survival、prey capture、escape success、energy efficiency、inference latency |

环境对照三组：Food Rich / Predator Rich / Resource Scarce。⚠️ 三组的**具体参数取值（食物密度、捕食者数等）尚未定义**，已登记进 `docs/参数总表.json` 的 `missing_required`；定值前不得在实现中自行填数。

## 8. 外部公开数据的使用政策

**原则：外部数据不用于训练，只用于两类用途——(a) 设计依据的文献引用；(b) 生物学合理性校验（报告可选小节，非必需）。**

| 资源 | 内容 | 允许的用法 | 禁止的用法 |
|---|---|---|---|
| 幼鱼运动 repertoire `[bib#17]` | 游泳/转向/捕食 bout 的运动统计 | 校验图：Arena 鱼群转向角分布、bout 时长 vs 真实幼鱼（"Biological plausibility" 可选小节） | 任何形式的训练 |
| 幼鱼全脑 ssEM `[bib#18]` | 电镜体积、部分神经元重建 | 引用佐证六类 fate、连接密度、距离代价规则的生物学来源 | 导入模型（原始对齐图像约 2.7 TB，且违背"不做真实大脑逐神经元复刻"的冻结范围） |
| Z-Brain 脑区图谱 `[bib#19]` | 幼鱼脑区图谱 | 给 6 个 developmental domains 对应真实脑区命名 | — |

**现场纪律（api/API与系统工程.md §7 Offline 红线，优先级最高）：** 演示现场不得依赖 OpenAI API、external model API、remote DB、remote asset CDN。若使用外部数据做校验图，**必须赛前预下载至 `data/external/` 并在报告中记录版本与来源**，现场零联网。
