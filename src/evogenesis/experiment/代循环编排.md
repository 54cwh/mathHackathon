# 代循环编排（experiment/）

> **管辖范围**：把「**评估一代 → 折算 `F` → 回填 `Individual` → `advance_generation` → 下一代**」串成可执行循环的**编排契约**：接口、字段映射、non-viable 处理、种子/ID、逐代产物、失败与状态。**不拥有**：选择/繁殖算法（`evolution/遗传繁殖与演化模型.md` §5–§6）、发育与 viability 判据（`development/RGCD数学模型.md` §7）、DanioNet→Arena 驱动（`pipeline/模型链装配.md` §4）、run 目录布局（本目录 `实验与评价体系.md` §5.1）、参数取值（`configs/`）。
> 状态：**v1.0 已定稿（冻结 2026-09-26）**。设计选择（无文献实测依据）逐项标 **D**。
> 上位：`问题定义与研究假设.md`、`evolution/遗传繁殖与演化模型.md`、`experiment/实验与评价体系.md`。

## 1. 链路

```text
initial_population(master_seed, experiment_id, n=population_size)      # gen 0（pipeline §2:26）
        │
        ▼  for g = 0, 1, …, generations-1
evaluate_population(individuals_g, master_seed, chain, arena_config, steps, g)   # pipeline（本节 §2）
        │  ├─ phenotypes_of(全部个体)         → 每体 viable / viability_reason
        │  └─ 仅 viable 进 DanioNet+Arena     → per_fish 指标（fish_id 为键）
        ▼
assemble_components(...) + fitness.composite_fitness(viable=mask)     # evolution §6（本节 §3）
        ▼
Individual(genome_id, fish_id, genome, fitness, viable, failure_reason)   # 回填
        ▼
advance_generation(parents_g, experiment_id, generation=g+1, seed_manager, evolution_config)  # evolution §5
        ▼  offspring（fish_id=None, viable=False, F=0）
   next gen；`evolution.population_bottleneck` 则终止（本节 §6）
```

## 2. 接口（owner：本文件；实现 `experiment/evolution_run.py`）

| 函数（文件） | 签名 / 作用 |
|---|---|
| `load_experiment_config`（`experiment/config.py`） | `load_experiment_config(path=DEFAULT_EXPERIMENT_CONFIG_PATH) → ExperimentConfig`；读 `configs/experiment.yaml`（`generations`；owner `实验与评价体系.md` §3.6）。`path=None` 显式报错（无内置默认值，`core §7`） |
| `evaluate_population`（**`pipeline/arena_episode.py`**，owner pipeline §2） | `evaluate_population(individuals, *, master_seed, chain, arena_config, steps=None, generation=0, device="cpu") → PopulationEvaluation`；评估一整代 |
| `assemble_individuals`（`evolution_run.py`） | `assemble_individuals(individuals, evaluation, *, arena_config, weights) → tuple[Individual, ...]`；按 §3 折算 `F` 并回填 |
| `run_evolution`（`evolution_run.py`） | `run_evolution(*, experiment_id, master_seed, generations, chain, arena_config, evolution_config, run_dir, environment_id="default", steps=None, device="cpu", forced_by_generation=None) → EvolutionRunResult`；`forced_by_generation: Mapping[int, (id_a, id_b)]` 对指定代传入 `advance_generation(forced_pair=…)`（Artificial Selection，`evolution §5`），其余代自然选择 |
| `to_chain_individuals`（`evolution_run.py`） | `to_chain_individuals(individuals, *, experiment_id) → tuple[ChainIndividual, ...]`；为 `fish_id=None` 的个体铸稳定 `fish_id` |

`PopulationEvaluation` 是 **pipeline 产出的边界对象**（owner = `pipeline/模型链装配.md` §2；本模块只消费）；字段：`phenotypes: tuple[ConnectomePhenotype, ...]`（与输入同序等长）、`episode: ArenaEpisodeResult | None`、`viable_indices: tuple[int, ...]`。

## 3. 评估 → `F` 回填（字段映射，定稿）

- **只评估发育 viable 的个体**（`RGCD §7`）：non-viable 无法构造 DanioNet，不入 Arena。
- **分量对齐全体**（长度 = 本代个体数），`evolution §6` 的四项取**原始量**（非 rate）：

| `components` 键 | 来源（`per_fish_log()`，仅 viable 有值） | non-viable |
|---|---|---|
| `survival` | `survival_steps` | `0.0` |
| `prey_capture` | `captures` | `0.0` |
| `escape_success` | `escape_successes` | `0.0` |
| `energy_efficiency` | `(energy_final − e_max) / survival_steps`（`metrics.energy_efficiency`） | `0.0` |

- `F = evolution.fitness.composite_fitness(components, viable=mask, weights=evolution_config.fitness_weights)`（代内 viable min-max）；权重唯一来源 `configs/evolution.yaml`。
- 回填 `Individual`：`viable`、`failure_reason`（non-viable 取 `phenotype.viability_reason`，viable 为 `None`）、`fitness=float(F[i])`、`fish_id`（viable=minted，non-viable=`None`）。**未评估与已判定 non-viable 的区分**由本循环保证：进入 `advance_generation` 前全体均已评估（`evolution §7`）。
- **边界（`energy_efficiency`）**：`survival_steps == 0`（首步即死）时分母无定义，该分量**记 0**——该边界由 `metrics.energy_efficiency`（`experiment §2.1`）统一处理。

## 4. 种子与稳定 ID（定稿）

- **`fish_id` 铸造**：本代第 `index` 个体的 Arena 身份 = `mint_id(experiment_id, "fish", generation, index)`；`index` 由 `core/ids.py::parse_index(genome_id)` 解析（`core §3`：不得用调用顺序）。gen 0 由 `pipeline.initial_population` 铸造，后代由 `to_chain_individuals` 铸造。
- **Arena 子种子（本文件新增，D）**：代循环内 `arena_seeds_for(master_seed, index=generation)`——`arena_spawn`/`arena_dynamics` 的实体序号 `t` 取**本代世代号**，使各代随机流独立；单代独立运行（`run_chain`）仍取 `t=0`。回写 `core §4.2` 的 episode 子种子映射。
- **发育/繁殖/选择**沿用上游：发育 `t=parse_index(genome_id)`；`selection` 取子代世代号；`crossover`/`mutation` 取 `t=generation·N+index`（`core §3`）。

## 5. 逐代产物（布局 owner `实验与评价体系.md` §5.1）

Fast Evolution Mode（`evolution §10`：同模拟、仅改输出）落盘为**每代一目录**：

```text
results/runs/<experiment_id>-s<seed>/
  metadata.json  config_snapshot/  seed.txt  git_commit.txt      # runlayout（owner）
  generations/g<gen:04d>/
    metrics.csv  population.jsonl  episodes.jsonl  events.jsonl  seed_summary.json   # 复用 experiment/run_artifacts.py 写者
    fitness.jsonl                # 逐个体：generation / genome_id / fish_id / viable / failure_reason / fitness(F)
  evolution.jsonl                # 逐代一行：generation / n_individuals / n_viable / F 均值方差(仅 viable) / bottleneck / event
                                 #   + Evolution Dashboard（交互与可视化 §8）聚合：p_A(=P(high_N)) / p_B(=P(high_H)) /
                                 #     phenotype_freq(四类架构档) / mean_neuron / mean_edge / mean_tau
```

- `evolution.jsonl` 的逐代聚合（`p_A`/`p_B`/`phenotype_freq`/`mean_neuron`/`mean_edge`/`mean_tau`）由 `genome §3`（阈值表型，已定稿阈值）与 `evaluation.phenotypes` 直接派生（`score.schema=evolution.schema.json`），服务 Evolution Dashboard（`交互与可视化.md §8`）。
- `fitness.jsonl`、`evolution.jsonl` 的字段为**本节新增**；`metrics/population/episodes/events/seed_summary` 沿用 `experiment §5.1/§5.2` 的字段与 schema。**整代无 viable**（`episode=None`）时只写 `fitness.jsonl`（无 arena 五件套）。`episode_id` 逐代固定 `"ep0001"`（每代独立目录，不冲突）。
- gen 目录名 `g<gen:04d>`（D）。
- `metadata.json.status`：`created → running → completed | bottleneck`（本循环更新）。

## 6. 失败与状态（定稿）

- 当代 viable `<2` → `advance_generation` 返回 `success=False` 且 `event="evolution.population_bottleneck"`；本循环把该 `event` 写入 `evolution.jsonl`（`event` 字段）、将 `metadata.json.status` 置 `bottleneck`，**终止**循环（不抛裸异常）。
- 单代无 viable（`episode=None`）：整代 `F=0`、`viable=False`；视为瓶颈前置态，记录后由 `advance_generation` 判定。
- 全程无任务终止信号（A9）：Arena 一律跑满 `episode_steps`。
