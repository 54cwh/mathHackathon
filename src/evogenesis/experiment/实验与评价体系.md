## 1. 复现与统计口径

### 1.1 种子与重复
Demo seed 与 research seeds 分离：`configs/demo_seed.yaml`（演示）与 `configs/experiment_seeds.yaml`（正式）。
正式结果的随机种子为 `seeds = [1103, 2207, 3301]`，最低重复数 3（`minimum_formal_replicates`），即 \(n=3\)，报告 mean ± std。

### 1.2 逐级统计口径（契约）
个体指标先在 **seed 内对个体取等权均值** → 该 seed 的一行；再沿 **seed 轴** 报告 mean ± std（样本标准差，n−1；`n < 2` 时 `std` 记 `null`）。逐个体原值全部保留在 `results/runs/<id>-s<seed>/metrics.csv`，任何人可重算。
实现：`experiment/metrics.py::aggregate_by_seed` / `summarise_over_seeds`；正式跑：`scripts/run_arena.py --experiment-id <id>`（每 seed 一个 run 目录，见 §5）。
**多 agent × 多 episode 的折叠（2026-09-26 定稿，Experiment C）**：seed 内折叠的观测数 = `n_agents × n_episodes`（Experiment C 为 12 × 3 = 36），`aggregate_by_seed` 写入的 `n_individuals` 即该值。因每个 `(agent, episode)` 格恒产生**恰好 1 条** `per_fish` 记录（日志含死鱼，见 §2.2），「36 条等权均值」与「agent 内先平均 episode、再跨 agent 平均」**数值相同**，故等权折叠无权重歧义。

### 1.3 报告纪律（契约）
1. **主指标是 `capture rate`（§2.1），不是接触转化。** 三个量都常被叫「捕获率」，必须标明是哪一个：
   - **`capture_rate`（主）**：`mean_i(captures_i / episode_steps)`，单位时间捕食数；
   - **`prey_capture`（诊断）**：`mean_i(captures_i / encounters_i)`，接触转化，受停留影响；
   - **汇总比值（诊断）**：`Σ captures_i / Σ encounters_i`，全部接触中得手的比例。
   三者数值差异很大（实测约 7 倍，证据见台账 `research/notes/契约决策记录.md`）。报告与路演建议主指标 + 绝对量并报；引用诊断量必须标注口径。
2. **引用 `prey_capture`（诊断）时必须并列偏态与绝对量。** `encounters` 的分布极右偏（少数长期蹲守在猎物集群中的个体会把分母刷到数百）。`captures/episode`、`encounters/episode` 等绝对量不得省略。

### 1.4 正式结果原则（契约）
- 不人工挑选最好的一次作为结论。
- Demo 可使用稳定 seed；正式结果必须来自固定 protocol。
- 所有图可回溯到 run directory。

## 2. 指标契约（唯一来源）

### 2.1 原始分量
| 指标 | 定义 | 值域 |
|---|---|---|
| survival | `survival_steps / episode_steps` | \([0,1]\) |
| **capture rate（主口径）** | `captures / episode_steps`（单位时间捕食数） | \([0,\infty)\)，典型 \(<1\) |
| `prey_capture`（诊断；与 `evolution` §6 的权重键 `prey_capture` 同名——选择用 F 取原始计数 `captures`，**非**本比值） | `captures / encounters`（`encounters == 0` ⇒ **未定义**，记 `None`；CSV 记空单元。**不得**记 `0.0`） | \([0,1]\) ∪ {未定义} |
| escape success | `escape_successes / max(predator_encounters, 1)`（分母 = **被锁定次数**，`arena` S7） | \([0,1]\)（`predator_encounters ≥ escape_successes` 时；分母为 0 的边界见下） |
| energy efficiency | \((E_i(T_i) - E_{max}) / T_i\)（净能量积累率简化式，口径见 `core/核心机制与数据流.md` §10 #12） | \((-\infty, 0]\)，MVP；`T_i=0`（首步即死）记 0 |

**主口径为何是 `capture rate` 而非接触转化（2026-09-26 用户裁定）**：默认捕获是**确定性**的（`growth.capture_success_prob = 1.0`，`arena §8 a`；可配置 <1），此时任何以「首次接触」为单位的**去重**口径（每猎物首接触、按接触段）都恒等于 1、零方差；而含重复计数的口径（每步每猎物各计一次 / 每鱼每步至多 1 次）分母随**停留步数**增长，比值实际度量「蹲守程度」而非捕食技巧（这正是右偏来源）。故主指标取**绝对速率** `captures / episode_steps`：无偏、可跨环境直接比较（实测 `food_rich` 捕获 21.3→27.3、`resource_scarce` 21.3→10.7 均直接体现）。
`prey_capture = captures / max(encounters, 1)`（**历史名**；`core` §10 #9 沿用此名）降为**诊断列**：其分母是尺寸门之前的纯距离接触计数（`arena` §18.3.2 **S6**），恒有 `captures ≤ encounters`；报告中引用必须注明其含义为「接触转化率，受停留影响」而非捕食成功率。**分母口径（2026-09-26 用户签署）**：`encounters == 0`（该个体整局无近距离接触 ⇒ **无出手机会**）时返回 `None`，与「有机会但未得手」（`captures == 0` 且 `encounters > 0` ⇒ 真 `0.0`）**区分开**。旧实现用 `max(encounters, 1)` 兜底，会把两者混为 `0.0`——那是把「没有机会出手」误报成「出手全部失败」。`capture_attempts` 为并列诊断列，不进任何分母。
实现现状：`experiment/metrics.py::capture_rate`（**主口径**）与 `prey_capture_rate`（诊断口径）均已实现；`metrics.csv` / `seed_summary.json` 均含 `capture_rate`。
启用 `growth.capture_success_prob < 1` 后，`prey_capture`（比值）成为真成功率，可另立「每 (鱼, 猎物) 首接触去重」的更严口径，届时同步本节。

**边界说明**：`escape_success_rate` 对分母 0 取 `max(·,1)` 且**不做上截断**（`escape_success_rate(3, 0) == 3.0`，`metrics.py` 按文档原式实现）；`predator_encounters == 0` 时该个体此项无定义，报告中须连同 `predator_encounters` 一起读。
> **同型歧义未在本次裁决内（2026-09-26）**：`escape_success` 与 `prey_capture` 的分母 0 兜底是同一类问题，且 `escape_success` 会因此产出 **大于 1 的值**。本次仅裁决了 `prey_capture`（改为 `None`）；`escape_success` **保持文档原式不变**，待用户另裁（见 `research/notes/契约决策记录.md`「遗留」）。

### 2.2 计数与事件语义（owner：`arena` §13 字段表）
| 计数 | 语义 |
|---|---|
| `survival_steps` | 该鱼存活的步数 |
| `captures` | 成功捕食次数（`arena.prey_captured` 事件） |
| `capture_attempts` | 「进过口」次数，每鱼每步**至多 1 次**：猎物 \(d < r_{capture}\) 且在前向锥内并判定了尺寸口径，**不论吃到与否**（吃到走 `prey_captured`，太小走 `capture_attempt`）；锥外不计 |
| `encounters` | 进入 `capture_radius` 的近距离接触计数，**每鱼每步至多 1 次**（首个进半径的猎物即计数并结束该步遍历；S6 纯距离、尺寸门之前） |
| `predator_encounters` | **被捕食者锁定的次数**（捕食者获得新目标时 +1；`arena` S7，**不是**近距接触计数）。= `escape success` 的分母 |
| `escape_successes` | 成功逃脱次数 |

恒有 `captures ≤ capture_attempts ≤ encounters`；`capture_attempts − captures` 即「进过口但吃不下」的次数。

> **已定稿（2026-09-26 回写 owner 口径）**：`encounters` 步内粒度 = **每鱼每步至多 1 次**（`arena §18.3.2 S6`）；`predator_encounters` = **被锁定（目标获取）次数**（`arena S7`），非近距接触。二者均为「计数而非事件」，仅出现在 `per_fish_log()` / `FishCard.metrics` 侧。

### 2.3 复合分与选择用适应度（分工，不可互替）
- **选择用 \(F\)**（上游已定，本文件只提供原始字段）：由 `evolution/遗传繁殖与演化模型.md` §6 产出；四项先在**代内 viable** 上 min-max 再加权，其中捕食分量取**原始计数 `captures`**（该节 §6:97 明确 `P=captures`），非比值。本文件不改变该口径。
- **显示分 `composite_fitness`**：四项 **rate** 直接加权，无代内归一；**捕食分量按条件式口径**（本文件定稿，2026-09-26）：
  - `growth.capture_success_prob = 1.0`（默认）→ 取**主口径 `capture_rate`**（绝对速率，无偏、可跨环境比较）；
  - 启用捕获随机化（`growth.capture_success_prob < 1`）→ 取 **`prey_capture`（真成功率）**——此时比值不再退化，是更恰当的技巧度量。
  权重唯一来源 `configs/evolution.yaml::fitness_weights`（漂移守护 `tests/test_evolution_config.py`），由生产调用方经 `load_evolution_config().fitness_weights` 注入 `metrics.composite_fitness`。**实现已对齐**：`metrics.episode_metrics` 按 `growth.capture_success_prob` 选捕食分量（`>=1` 取 `capture_rate`，`<1` 取 `prey_capture`）；`COMPOSITE_WEIGHTS` 仅为冻结镜像默认值、键名 `prey_capture` 为历史名。
- 诊断量 `prey_capture` 仅在「启用捕获随机化」时作为复合分的捕食分量；**其余情况不进任何复合分或适应度**，只作报告与诊断。
- 跨环境比较 \(F\) 须用**原始指标**，不可用代内 min-max 后的分数。

### 2.4 效率与资源量
\[
\text{active-edge efficiency} = \frac{\text{TaskPerformance}}{\text{ActiveConnections} \times \text{Timesteps}}
\]
- `TaskPerformance` = `composite_fitness`（§2.3）；分母单位「活跃连接数 × 步数」，量纲 \(\text{连接}^{-1}\,\text{步}^{-1}\)。命名与图论 efficiency 区分 `[bib#22]`。
- 单独报告：`parameter count`、`active edges`、`inference latency`、`FLOPs`、`peak memory`。
- 测量协议（符号：\(N\) = padding 宽度 = `development.max_neurons`（现 48，int ≥ 1）；\(D\) = `network.sensory_dim`（现 12，int ≥ 1）；\(E_A\) = 支撑 \(A\) 的非零连接数（int ≥ 0）；\(N_{act}\) = 活跃（非 padding）神经元数（int，\(0 \le N_{act} \le N\)））：
  - **inference latency**：单步前向（batch = **本次评估的 agent 数 B**（2026-09-26 定稿；Experiment C 取 B = 12，对应生产场景「12 个 agent 同时推进一步」；其余场景 B = 1），`float32`，与生产同 device，**无梯度** `torch.no_grad()`——推理口径，不含 autograd 开销），先 warmup \(W\) 次再计时 \(I\) 次；报 p50 / p95（单位 ms）。\(W = 20\)、\(I = 200\) 为**已定稿**（2026-09-27 用户签署）。
  **与结构量的口径差异（须并注）**：`MACs` / `FLOPs` 是**单个体**结构量（\(\text{MACs}_{impl} = N^2 + N D\) **不含 batch 因子**），而 latency 是**批量一次前向**的 wall-clock。两处数字不得跨口径比较。
  - **FLOPs**：单步前向，**两个口径均报**：\(\text{MACs}_{impl} = N^2 + N D\)（完整稠密矩阵，含 padding 与零边）；\(\text{MACs}_{theo} = E_A + N_{act} D\)（仅活跃部分，体现结构稀疏）。共同约定：含输入投影 \(U x\)、**不含**非线性；\(\text{FLOPs} = 2 \times \text{MACs}\)。
  - **peak memory**：`tracemalloc` 追踪的 Python 分配峰值（\(\text{tracemalloc.get\_traced\_memory}()[1]\)，单位 B，范围＝整 episode）；不含 torch 原生分配，需计入时改用进程 RSS（P2）。
- **实现状态**：`parameter count` / `active edges` 由结构直接读出；`latency` / `FLOPs` / `peak memory` 由 `experiment/measure.py` 实现（`tests/test_measure.py` 守护）；baseline（MLP / GRU / Fixed Sparse RNN）见 `connectome/baselines.py`（§8），Experiment C 的横向表可直接产出。

### 2.5 距离量（Experiment B 用；不在此重复定义）
`d_edge = ‖A − A'‖₁ / N²`、`d_τ = (1/N) Σ |τ_i − τ'_i|`、`ΔB`（四维不合成标量）——定义 owner 为 `development/RGCD数学模型.md` §12；`experiment/metrics.py::edge_distance` / `tau_distance` 为其二值实现。

## 3. 实验协议（A–F）

共有前提：使用 §1.1 的 seed 集；每项实验给出 目的 / 自变量 / 因变量 / 预算 / 产物 / 判据。A–F 均为**必做**（对应 `docs/验收清单.md` Research 段）。

### 3.1 Experiment A — Genome → Architecture
- **目的**：刻画「基因组 → 结构统计」的分布。
- **自变量**：随机生成的 **48 个 genome**（与 `configs/evolution.yaml::population_size` 对齐；随机源由 `core` seed manager 派生，禁自建随机源）。
- **处理**：每个 genome 跑**完整发育**（RGCD）。
- **记录**：motif affinity、GRN final states、neuron count、cell-type distribution、edge density、tau distribution。
- **产物**：结构统计表 + 分布图。

### 3.2 Experiment B — Single-base Mutation
- **代表 haplotype**：固定 seed 下 **generation-0 的首个个体**（记录其 `genome_id`）。
- **处理**：对该 haplotype 的 **256 个位点**逐位做 deterministic alternative-base mutation（位点方向定义 owner：`genome/生物学与进化遗传学基础.md` §5）。
- **计算**：\(\Delta Expression = |E - E'| / E\) 的**逐 motif 均值**；`d_edge`、`d_τ`、`ΔB`（引 §2.5）。
- **Genome Sensitivity Map**：横轴 256 个位点，纵轴 Δ 大小，按四位点 / motif 分组聚合的**条形热图**。
- **预算**：256 个位点**全部逐位跑**（每位做完整发育；不降采样）。

### 3.3 Experiment C — Baseline
- **模型**：MLP、GRU、Fixed Sparse RNN、DanioNet；三个 baseline 的实现与尺寸反解见 `connectome/DanioNet设计规范.md` §8（`connectome/baselines.py`，连接数 196 / 200 / 190，均满足判据）。
- **控制**：相同数据；相同训练预算（BC：`K=20` mini-batch，`learning/行为克隆学习.md` §3）；参数量同一数量级（**按连接（权重）数比较**，`|log10 N_base − log10 N_ours| ≤ 1`，`DanioNet设计规范.md` §8）；相同 evaluation episodes（每条件 3 seed × 每 seed **12 agent × 3 evaluation episode**；评估 episode 子种子走 `core §4.2` 的 `arena_eval_spawn=15` / `arena_eval_dynamics=16`，`t` = 评估内 0 起 episode 序号，**全模型共享**）。**模型评估由 `scripts/run_chain.py`（DanioNet 驱动）执行**；`scripts/run_arena.py`（ExpertPolicy 驱动）只用于环境 pre-check / 基线，**不用于模型评估**（`learning §5`）。
- **指标**：survival、prey capture、escape success、energy efficiency、inference latency、FLOPs、parameter count、active edges。
- **产物**：对比表（含方差与重复次数）。
- **实现状态（2026-09-26 已接）**：编排 `experiment/baseline_run.py`、薄 CLI `scripts/run_baselines.py`。流程：同 `trajectories/` → 三基线 `train_bc(sign_constrained=False)` / DanioNet `train_bc(sign_constrained=True)`（同 K=20 / batch=64 / Adam / 同 λ）→ `pipeline.drive_arena_with_ids` 驱动 Arena。**评估规模（已定稿，2026-09-26 用户签署；原「草案待确认」解除）**：每模型每 seed **12 agent × 3 evaluation episode**。要点：
  - **评估 episode 子种子**：`core §4.2` 的 `arena_eval_spawn=15` / `arena_eval_dynamics=16`，`t` = 评估内 0 起 episode 序号，**全模型共享**（「相同 evaluation episodes」红线）。与采集的 `arena_spawn`/`arena_dynamics` **刻意解耦**（后者已被 `collect` 的 episode 序号与代循环的 `generation` 共占，且 `arena_seeds_for` 与 `episode_seed` 逐字等价 —— 复用会使评估局落在训练数据的环境实例上）。
  - **DanioNet 取前 12 个 viable**：`viable_pairs(...)[:12]`（保序 ⇒ 取**最低 index** 的 12 个 viable；顺序无关，合规 `core §3` 的稳定 ID 要求）。`n_danio = 400`（实测 viable 率 8–10%，P(≥12) ≈ 1；发育 ~15 ms/个体，故加大候选近乎免费）。**降级语义**：viable < 12 时**抛错**（带 seed / n_danio / 实际数）；`--allow-partial` 显式开关改按 available 评估并逐模型记实际 `n_agents`。
  - **`bc` 采样序号的 `t`**：基线由铸出的稳定 ID 解析（`t = parse_index(fish_id)`，基线索引基 `BASELINE_INDEX_BASE = 1000`，与 DanioNet 的 `[0, n_danio)` 分区以保证 experiment 级唯一性）；DanioNet 用配子级规则 `t = generation·n_danio + index`。**两家族均不再固定取模型槽位**（旧实现令同模型 12 个 agent 拿到相同初值与相同 BC 采样，实验无效）。
  - **复杂度口径**：DanioNet 报 12 个个体的**等权均值**（结构量/FLOPs 均值，latency 为 batch = 12 的一次前向），`note` 记极差；基线三模型逐 agent 恒等。`MACs`/`FLOPs` 为**单个体**结构量、不含 batch 因子（§2.4）。
  - **训练（不可改 `train_bc` 的 batch=1 契约）**：DanioNet 先**逐个体** `danionet_of([phenotype])` + `train_bc`，再把各自 `theta` 注入 batch-12 评估网（范式同 `experiment/learning_run.py`）。
  - **确定性前提**：`core §3` 的「禁止 AI 填空」条款见 `AGENTS.md`（本节旧引的「§2.1」是「原始分量」，不含该字样）。产物：每 seed `<run>/metrics.csv`（含 `model` 列）+ `results/tables/<experiment_id>_baselines.json`（schema = `schemas/baseline_comparison.schema.json`）。**公平性声明**：三基线 `(ω, v)` 与 DanioNet **同映射**（\(\omega=\tanh\)、\(v=\sigma\)，`connectome §8`），故 \(v\in[0,1]\)，与 `Arena` 读出**一致**（原基线两维同用 `tanh` 会使约一半速度被截为 0；2026-09-26 已统一为 σ 读出）。守护：`tests/test_baseline_run.py`。

### 3.4 Experiment D — Ablation

实现口径 owner：`connectome/DanioNet设计规范.md` §9。**选定 3 个消融臂**（对应验收「3 ablations」），均只改一个变量：

| 臂 | 变更（唯一变量） | 运行方式 |
|---|---|---|

### 3.5 Experiment E — Robustness
**目的**：在不重发育的前提下，测「删掉已发育网络的**活跃边**」对行为与适应度的退化影响（稳定性证据，`docs/赛题补充说明.md`「稳定性」）。

**底物（substrate，已定稿）**：每个 formal seed 取该 seed 初始种群（`n_danio` 默认 **48**）中**首个 viable** 个体，经 `pipeline`（`motif 目录 → q(G) → develop → DanioNet`）构造**训练前**（`ΔW=0`）网络。实测（2026-09-27）：首个 viable 的 `index` 与 `n_danio=12` **完全一致**（index 7/4/8），取 48 基本消除「该 seed 无 viable」空底物，且与 §3.6 的演化规模一致。

**删边口径（已定稿）**：仅在**活跃支撑边** \(\text{support}=A\land M\)（`net.support`）上，用 `core §3` 的 `robustness` 命名空间对该 seed 的底物**无放回**均匀抽取 \(k=\mathrm{round}(f\cdot|\text{support}|)\) 条边；把这些边的**有效权重清零**（`support` / `support_sign0` / `support_f32` 置 0、`weights0` 置 0，`Θ` 相应位置被支撑屏蔽）。其余权重与 \(W^{(0)}\) **逐元素不变**（不重发育、不重训练）；自环本就不存在。

**条件**：\(f\in\{0.00\,(\text{对照}),\,0.05,\,0.10,\,0.20\}\)；`0.05 / 0.10 / 0.20` 为已定稿取值，`0.00` 为退化基线（新增，用于算 \(\Delta\)）。

**评估**：同 §3.3 口径——1 agent × 1 episode，`drive_arena_with_ids`；对照与各删除组**共用同一底物 \(W^{(0)}\) 与同一 arena 子种子**（`generation=0` → `t=0`），故指标差归因于删边。

**因变量（2026-09-27 实测修订，已定稿）**：实测 1 agent × 1 episode 下 **outcome 指标无区分力**（600 步 survival 恒 1、captures 0–1、复合分近常数），故**主指标取「行为发散」**——把控制网络跑出的**同一 observation 序列**回放给删边网络，比较逐步动作 \(\overline{|\Delta\omega|}\)、\(\overline{|\Delta v|}\)（开环、确定性、对被删边敏感；实测随 \(f\) 增至 \(0.04\text{–}0.11\) / \(0.004\text{–}0.012\)）。outcome 指标（§2.1 分量 + 复合分）作**次要**证据，其退化量先按 seed 对 \(f=0\) 取差、再跨 seed 汇总：

\[
\Delta_m(f)=m(f)-m(0),\qquad r_m(f)=\frac{m(f)-m(0)}{\lvert m(0)\rvert}\quad(m(0)\neq 0).
\]

**重复与随机源**：formal seeds `[1103,2207,3301]`（§1.1，n=3，mean±std）；删边随机源 = `core §3` 的 `robustness`（id=14），实体 \(t=\text{seed\_slot}\cdot\lvert\text{fractions}\rvert+\text{fraction\_index}\)（确定性，跨 seed/条件独立）。

**产物**：`results/tables/<experiment_id>_robustness.json`（schema `schemas/robustness.schema.json`）；CLI `scripts/run_robustness.py`（薄壳），业务 owner `experiment/robustness_run.py`。

**判据与声明**：给出「删边比例 → **行为发散（主）** + outcome 退化（次）」曲线与表；结论须声明 n=3、每 seed 单底物，功率有限，只作**指示性**退化证据。

> **状态：已定稿（2026-09-27 用户签署）**。底物（每 seed 首个 viable、`n_danio=48`）、删边口径（结构性清零 `support`）、因变量（主指标行为发散 + outcome 次要）三项定稿；`robustness.json` 的 `status` 字段置 `confirmed`。依据：本节 2026-09-27 实测（outcome 无区分力、行为发散敏感）。

**设计原则：单因子对照。** 每个环境相对基线（`configs/default_arena.yaml`：`n_prey=24`、`n_predators=3`）**只改变一个驱动**，使环境效应可归因。

| 环境 | `environment_id` | `n_prey` | `n_predators` | `prey_regrowth_steps` | 隔离的驱动 |
|---|---|---|---|---|---|
| 基线（非三组之一） | `default` | 24 | 3 | 25 | — |
| Food Rich | `food_rich` | **48** | 3 | **13** | 猎物可得性 ↑ |
| Predator Rich | `predator_rich` | 24 | **6** | 25 | 捕食压力 ↑ |
| Resource Scarce | `resource_scarce` | **12** | 3 | **50** | 猎物可得性 ↓ |

**派生约定（不新增旋钮）**：`prey_regrowth_steps = ceil(600 / n_prey)`（向上取整：不早于名义速率回复；默认 `600/24 = 25`，与 `default_arena.yaml` 一致），故它随 `n_prey` 机械确定。
不用 `round`：`600/48 = 12.5` 是平局，`round` 走银行家舍入得 `12`，语义含混；`ceil` 无歧义。

**未改变的量（必须保持不变，否则对照失效）**：`world`（含 `episode_steps=600`）、`sensing`、`energy`、`growth`（含 `capture_radius`、`κ`、前向锥）、`actors` 全部取默认；`n_fish=12`、`n_obstacles=6` 不变（**本节的 12 鱼是 `ExpertPolicy` pre-check/环境对照的规模**；Experiment F 的演化评估用 48 个体，由 `pipeline/arena_episode.py` 按 viable 数覆盖 `n_fish`，`arena §3`）。实验环境**不得**暗改契约值。

**结论（均须写进报告，诚实版）**：
1. **本 pre-check 无稳健区分力**：最大 |d| 为 `resource_scarce` 的 `energy_efficiency`（−1.79）与 `capture_rate`（−1.43），**均未达 1.9σ**；`predator_rich` 现无明显效应（`escape_success` d=−0.12）。n=3 且 12 鱼，**功率不足**，不可据本表断言任何环境效应。
2. **绝对量仍有区分、比值仍弱**：`food_rich` 捕获 21.3 → 27.3（+28%）、遭遇 266 → 592；`resource_scarce` 捕获 → 10.7（−50%）、遭遇 → 30。比值 `prey_capture` 的 d 均 <0.2——再次印证「比值被密度同时抬高分子分母而掩盖效应」，E-F 记录项**必须含绝对量**（§3.6）。
3. **与旧表的差异属真实修正**：旧 `predator_rich` 的强 d 值是随机流耦合时期的产物，已随 A14 拆分作废。

**排期建议（更新）**：正式 E-F **必须走 §3.6 的 pilot 门**（48 个体 × 10 代 pilot，以同环境 seed 间 spread 作噪声带）判断区分力；本 12 鱼 / n=3 pre-check 只作**管道可用性**证据，**不得**作为「环境有效应」的依据。

### 5.2 产物字段与 schema 归属
- **JSON 产物**已各建 JSON Schema 于 `schemas/` 并由测试校验：`run_metadata.schema.json`（`metadata.json`）、`population.schema.json`（`population.jsonl`）、`episodes.schema.json`（`episodes.jsonl`）、`seed_summary.schema.json`、`run_table_summary.schema.json`（`results/tables/<id>_summary.json`）；§3.8 另有 `learning.schema.json` / `learning_summary.schema.json`；§3.3 有 `baseline_comparison.schema.json`（`results/tables/<id>_baselines.json`）；§3.4 有 `ablation_comparison.schema.json`（`results/tables/<id>_ablations.json`）；§3.9 有 `penetrance.schema.json`（`results/tables/<id>_penetrance.json`）；代循环另有 `fitness.schema.json` / `evolution.schema.json`（`代循环编排.md` §5）。生产者为 `experiment/runlayout.py` / `run_artifacts.py` / `evolution_run.py`；守护 `tests/test_run_artifacts_schema.py`。
- **`metadata.json` 的 schema 归属（已定）**：另建 `schemas/run_metadata.schema.json`（承载 `config / status / arena_config_resolved / created_at`）；`schemas/experiment.schema.json` 定位为**实验描述符**（输入侧：`model_config / arena_config / evolution_config`），二者不同物。
- **`metrics.csv`** 用字段表（CSV 不建 schema）：`seed`、`fish_id` + §2.1 指标 + 原始计数（含诊断列 `capture_attempts`）+ **行内附加键**（按首现顺序，如 BC 生命周期的 `phase`/`generation`，由 `run_artifacts.write_metrics_csv` 保留、不静默丢弃）。**Experiment C 的附加列**：`model` / `agent` / `episode`（三者由 `baseline_run` 的行组装配带；`episode` 为必需 —— 同一 `fish_id` 跨 3 局重复，无此列无法区分行来自哪一局）。
- **`metadata.json`** 字段（`schemas/run_metadata.schema.json`，已建）：`experiment_id`、`seed`、`config`、`status`、`arena_config_resolved`、`extras`、`created_at`、`mlflow_run_id`（run 终态登记后回写，未登记为 `null`）；与 `schemas/experiment.schema.json` 为不同物（`metadata.json` = run 产物；`experiment.schema.json` = 实验描述符）。
- **`events.jsonl`（已定）**：schema = `schemas/event_log.schema.json`；首行 header 承载 run 级上下文（`experiment_id / episode_id / environment_id / generation / episode_seed / n_events`），其后逐条 arena 事件 `{seq,type,step,payload}`（信封/词表 owner = `arena §18.4`）。落盘业务逻辑 owner = `experiment/events.py`，`scripts/run_arena.py` / `run_chain.py` 调用。
