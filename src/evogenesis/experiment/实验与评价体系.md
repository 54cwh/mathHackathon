# 实验设计与评价体系

> **管辖范围**：实验协议、指标定义、`results/runs` 目录布局与正式结果原则；环境对照三组取值。（层级与归属见 `AGENTS.md`「文档层级与优先级」。）

## 1. Reproducibility
Demo seed 与 research seeds 分离。

正式结果至少：

\[
n=3
\]

random seeds，报告 mean ± std。

**统计口径（2026-09-26 定，回答 §阅读问题 #1）**：个体指标先在 **seed 内对个体取等权均值** → 该 seed 的一行；再沿 **seed 轴** 报告 mean ± std（样本标准差，n-1；`n < 2` 时 `std` 记 `null`）。逐个体原值全部保留在 `results/runs/<id>/metrics.csv`，任何人都能重算。实现：`experiment/metrics.py::aggregate_by_seed` / `summarise_over_seeds`；正式跑：`scripts/run_arena.py --experiment-id <id>`（每 seed 一个 run 目录，见 §11）。

## 2. Experiment A — Genome → Architecture

## 3. Experiment B — Single-base Mutation
对代表性 haplotype 的 256 positions 逐位做 deterministic alternative-base mutation。

计算：

\[
\Delta Expression,\quad d_{edge},\quad d_\tau,\quad \Delta Behavior
\]

生成 Genome Sensitivity Map。

## 4. Experiment C — Baseline
- MLP
- GRU
- Fixed Sparse RNN
- DanioNet

控制：
- 相同数据
- 相同训练预算
- 参数量同一数量级
- 相同 evaluation episodes

指标：
- survival
- prey capture
- escape success
- energy efficiency
- inference latency
- parameter count
- active edges

指标定义（供 §9 与 fitness 复用；出处 `research/reference/design-basis-metrics.md`）：
- survival = `survival_steps / episode_steps`
- prey capture = `captures / max(capture_attempts, 1)`；**`capture_attempts` 口径（2026-09-26 用户裁定，已实现）**：每鱼每步**至多 1 次** —— 猎物进入 `d < r_capture` **且在猎人前向锥内**并**判定了尺寸口径**，**不论吃到与否**（吃到走 `arena.prey_captured`，太小走 `arena.capture_attempt`）；锥外不计。故恒有 `capture_attempts ≥ captures`；该比值度量「**有机会下口时，是否挑对了吃得下的猎物**」。实现：`arena/env.py`（计数器）+ `experiment/metrics.py::prey_capture_rate`；契约见 `arena/Danio_Arena设计与实现说明.md` §8 与 §13 字段表。**`composite_fitness` 随之可算。**
- escape success = `escape_successes / max(predator_encounters, 1)`
- energy efficiency = 净能量积累率简化式 \(r_i=(E_i(T_i)-E_{max})/T_i\)（MVP；口径见 `core/核心机制与数据流.md` §10 #12）
- inference latency = 单步前向延迟 p50/p95（warmup 后测得）
- **选择用 \(F\) 不属本节**：本节只定义**原始分量**与逐个体**显示分**（`experiment/metrics.py::composite_fitness`＝四项 rate 直接加权，无代内归一）。用于选择的 \(F\) 由 `evolution/遗传繁殖与演化模型.md` §6 产出（四项先在**代内 viable** 上 min-max 再加权）；两者不可互替。

> H2 需专门分析：connectome 与行为矩阵的 **Mantel 检验**（本表未单列，见 `问题定义与研究假设.md` §2 映射表）`[bib#21]`。

## 8. Mendelian validation
大量 offspring 验证 AaBb × AaBb。显示 empirical ratio，并计算：

\[
\chi^2=\sum_i\frac{(O_i-E_i)^2}{E_i}
\]

统计波动属于模型正常结果。

## 9. Active-edge efficiency
\[
\text{active-edge efficiency}=
\frac{TaskPerformance}
{ActiveConnections\times Timesteps}
\]
（命名与图论 efficiency 区分 `[bib#22]`；旧称 `Efficiency` 易混淆。）

同时单独报告：
- parameter count
- active edges
- latency
- peak memory（可测时）

## 10. 正式结果原则
- 不人工挑选最好一次作为结论。
- Demo 可使用稳定 seed。
- 正式结果必须来自固定 protocol。
- 所有图可回溯到 run directory。

## 11. Run 目录
```text
results/runs/<experiment_id>-s<seed>/   # 每个 seed 一个 run 目录（experiment_id 由调用方给定）
  metadata.json               # run_experiment.py 写
  config_snapshot/
  arena_config_resolved.json  # 实际生效的 ArenaConfig 快照（原始 YAML 会与解析值漂移）
  metrics.csv                 # 逐个体一行：指标 + 原始计数
  population.jsonl            # 逐个体一行：轨迹幅度等，供作图
  episodes.jsonl              # 逐 episode 一行：事件计数 + 吞吐
  seed_summary.json           # 该 seed 的个体等权均值
  seed.txt
  git_commit.txt
  plots/                      # ⏳ 尚未产出（make_figs.py 待写）

跨 seed 的 mean ± std 落在 `results/tables/<experiment_id>_summary.json`。
Arena 侧驱动与产物写入：`scripts/run_arena.py`（目录布局仍由 `scripts/run_experiment.py` 单独负责）。
```
