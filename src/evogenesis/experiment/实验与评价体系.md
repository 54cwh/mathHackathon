## 1. 复现与统计口径

### 1.1 种子与重复
Demo seed 与 research seeds 分离：`configs/demo_seed.yaml`（演示）与 `configs/experiment_seeds.yaml`（正式）。
正式结果的随机种子为 `seeds = [1103, 2207, 3301]`，最低重复数 3（`minimum_formal_replicates`），即 \(n=3\)，报告 mean ± std。

### 1.2 逐级统计口径（契约）
个体指标先在 **seed 内对个体取等权均值** → 该 seed 的一行；再沿 **seed 轴** 报告 mean ± std（样本标准差，n−1；`n < 2` 时 `std` 记 `null`）。逐个体原值全部保留在 `results/runs/<id>-s<seed>/metrics.csv`，任何人可重算。
实现：`experiment/metrics.py::aggregate_by_seed` / `summarise_over_seeds`；正式跑：`scripts/run_arena.py --experiment-id <id>`（每 seed 一个 run 目录，见 §5）。

### 1.3 报告纪律（契约）
1. **主指标是 `capture rate`（§2.1），不是接触转化。** 三个量都常被叫「捕获率」，必须标明是哪一个：
   - **`capture_rate`（主）**：`mean_i(captures_i / episode_steps)`，单位时间捕食数；
   - **`prey_capture`（诊断）**：`mean_i(captures_i / encounters_i)`，接触转化，受停留影响；
   - **汇总比值（诊断）**：`Σ captures_i / Σ encounters_i`，全部接触中得手的比例。
   三者数值差异很大（实测约 7 倍，证据见台账 `research/notes/契约决策记录.md`）。报告与路演建议主指标 + 绝对量并报；引用诊断量必须标注口径。
2. **引用 `prey_capture`（诊断）时必须并列偏态与绝对量。** `encounters` 的分布极右偏（少数长期蹲守在猎物集群中的个体会把分母刷到数百）。`captures/episode`、`encounters/episode` 等绝对量不得省略。

### 1.4 正式结果原则（契约）
- 不人工挑选最好的一次作为结论。
- Demo 可使用稳定 seed；正式结果必须来自固定 protocol。
- 所有图可回溯到 run directory。

## 2. 指标契约（唯一来源）

### 2.1 原始分量
| 指标 | 定义 | 值域 |
|---|---|---|
| survival | `survival_steps / episode_steps` | \([0,1]\) |
| **capture rate（主口径）** | `captures / episode_steps`（单位时间捕食数） | \([0,\infty)\)，典型 \(<1\) |
| `prey_capture`（诊断；与 `evolution` §6 的权重键 `prey_capture` 同名——选择用 F 取原始计数 `captures`，**非**本比值） | `captures / max(encounters, 1)` | \([0,1]\) |
| escape success | `escape_successes / max(predator_encounters, 1)`（分母 = **被锁定次数**，`arena` S7） | \([0,1]\)（`predator_encounters ≥ escape_successes` 时；分母为 0 的边界见下） |
| energy efficiency | \((E_i(T_i) - E_{max}) / T_i\)（净能量积累率简化式，口径见 `core/核心机制与数据流.md` §10 #12） | \((-\infty, 0]\)，MVP；`T_i=0`（首步即死）记 0 |

**主口径为何是 `capture rate` 而非接触转化（2026-09-26 用户裁定）**：默认捕获是**确定性**的（`growth.capture_success_prob = 1.0`，`arena §8 a`；可配置 <1），此时任何以「首次接触」为单位的**去重**口径（每猎物首接触、按接触段）都恒等于 1、零方差；而含重复计数的口径（每步每猎物各计一次 / 每鱼每步至多 1 次）分母随**停留步数**增长，比值实际度量「蹲守程度」而非捕食技巧（这正是右偏来源）。故主指标取**绝对速率** `captures / episode_steps`：无偏、可跨环境直接比较（实测 `food_rich` 捕获 21.3→27.3、`resource_scarce` 21.3→10.7 均直接体现）。
`prey_capture = captures / max(encounters, 1)`（**历史名**；`core` §10 #9 沿用此名）降为**诊断列**：其分母是尺寸门之前的纯距离接触计数（`arena` §18.3.2 **S6**），恒有 `captures ≤ encounters`；报告中引用必须注明其含义为「接触转化率，受停留影响」而非捕食成功率。`capture_attempts` 为并列诊断列，不进任何分母。
实现现状：`experiment/metrics.py::capture_rate`（**主口径**）与 `prey_capture_rate`（诊断口径）均已实现；`metrics.csv` / `seed_summary.json` 均含 `capture_rate`。
启用 `growth.capture_success_prob < 1` 后，`prey_capture`（比值）成为真成功率，可另立「每 (鱼, 猎物) 首接触去重」的更严口径，届时同步本节。

**边界说明**：`escape_success_rate` 对分母 0 取 `max(·,1)` 且**不做上截断**（`escape_success_rate(3, 0) == 3.0`，`metrics.py` 按文档原式实现）；`predator_encounters == 0` 时该个体此项无定义，报告中须连同 `predator_encounters` 一起读。

### 2.2 计数与事件语义（owner：`arena` §13 字段表）
| 计数 | 语义 |
|---|---|
| `survival_steps` | 该鱼存活的步数 |
| `captures` | 成功捕食次数（`arena.prey_captured` 事件） |
| `capture_attempts` | 「进过口」次数，每鱼每步**至多 1 次**：猎物 \(d < r_{capture}\) 且在前向锥内并判定了尺寸口径，**不论吃到与否**（吃到走 `prey_captured`，太小走 `capture_attempt`）；锥外不计 |
| `encounters` | 进入 `capture_radius` 的近距离接触计数，**每鱼每步至多 1 次**（首个进半径的猎物即计数并结束该步遍历；S6 纯距离、尺寸门之前） |
| `predator_encounters` | **被捕食者锁定的次数**（捕食者获得新目标时 +1；`arena` S7，**不是**近距接触计数）。= `escape success` 的分母 |
| `escape_successes` | 成功逃脱次数 |

恒有 `captures ≤ capture_attempts ≤ encounters`；`capture_attempts − captures` 即「进过口但吃不下」的次数。

> **已定稿（2026-09-26 回写 owner 口径）**：`encounters` 步内粒度 = **每鱼每步至多 1 次**（`arena §18.3.2 S6`）；`predator_encounters` = **被锁定（目标获取）次数**（`arena S7`），非近距接触。二者均为「计数而非事件」，仅出现在 `per_fish_log()` / `FishCard.metrics` 侧。

### 2.3 复合分与选择用适应度（分工，不可互替）
- **选择用 \(F\)**（上游已定，本文件只提供原始字段）：由 `evolution/遗传繁殖与演化模型.md` §6 产出；四项先在**代内 viable** 上 min-max 再加权，其中捕食分量取**原始计数 `captures`**（该节 §6:97 明确 `P=captures`），非比值。本文件不改变该口径。
- **显示分 `composite_fitness`**：四项 **rate** 直接加权，无代内归一；**捕食分量按条件式口径**（本文件定稿，2026-09-26）：
  - `growth.capture_success_prob = 1.0`（默认）→ 取**主口径 `capture_rate`**（绝对速率，无偏、可跨环境比较）；
  - 启用捕获随机化（`growth.capture_success_prob < 1`）→ 取 **`prey_capture`（真成功率）**——此时比值不再退化，是更恰当的技巧度量。
  权重唯一来源 `configs/evolution.yaml::fitness_weights`（漂移守护 `tests/test_evolution_config.py`），由生产调用方经 `load_evolution_config().fitness_weights` 注入 `metrics.composite_fitness`。**实现已对齐**：`metrics.episode_metrics` 按 `growth.capture_success_prob` 选捕食分量（`>=1` 取 `capture_rate`，`<1` 取 `prey_capture`）；`COMPOSITE_WEIGHTS` 仅为冻结镜像默认值、键名 `prey_capture` 为历史名。
- 诊断量 `prey_capture` 仅在「启用捕获随机化」时作为复合分的捕食分量；**其余情况不进任何复合分或适应度**，只作报告与诊断。
- 跨环境比较 \(F\) 须用**原始指标**，不可用代内 min-max 后的分数。

### 2.4 效率与资源量
\[
\text{active-edge efficiency} = \frac{\text{TaskPerformance}}{\text{ActiveConnections} \times \text{Timesteps}}
\]
- `TaskPerformance` = `composite_fitness`（§2.3）；分母单位「活跃连接数 × 步数」，量纲 \(\text{连接}^{-1}\,\text{步}^{-1}\)。命名与图论 efficiency 区分 `[bib#22]`。
- 单独报告：`parameter count`、`active edges`、`inference latency`、`FLOPs`、`peak memory`。
- 测量协议（符号：\(N\) = padding 宽度 = `development.max_neurons`（现 48，int ≥ 1）；\(D\) = `network.sensory_dim`（现 12，int ≥ 1）；\(E_A\) = 支撑 \(A\) 的非零连接数（int ≥ 0）；\(N_{act}\) = 活跃（非 padding）神经元数（int，\(0 \le N_{act} \le N\)））：
  - **inference latency**：单步前向（batch = 1，`float32`，与生产同 device），先 warmup \(W\) 次再计时 \(I\) 次；报 p50 / p95（单位 ms）。\(W = 20\)、\(I = 200\) 为**草案待确认**（实现先行，数值待用户签署）。
  - **FLOPs**：单步前向，**两个口径均报**：\(\text{MACs}_{impl} = N^2 + N D\)（完整稠密矩阵，含 padding 与零边）；\(\text{MACs}_{theo} = E_A + N_{act} D\)（仅活跃部分，体现结构稀疏）。共同约定：含输入投影 \(U x\)、**不含**非线性；\(\text{FLOPs} = 2 \times \text{MACs}\)。
  - **peak memory**：`tracemalloc` 追踪的 Python 分配峰值（\(\text{tracemalloc.get\_traced\_memory}()[1]\)，单位 B，范围＝整 episode）；不含 torch 原生分配，需计入时改用进程 RSS（P2）。
- **实现状态**：`parameter count` / `active edges` 由结构直接读出；`latency` / `FLOPs` / `peak memory` 由 `experiment/measure.py` 实现（`tests/test_measure.py` 守护）；baseline（MLP / GRU / Fixed Sparse RNN）见 `connectome/baselines.py`（§8），Experiment C 的横向表可直接产出。

### 2.5 距离量（Experiment B 用；不在此重复定义）
`d_edge = ‖A − A'‖₁ / N²`、`d_τ = (1/N) Σ |τ_i − τ'_i|`、`ΔB`（四维不合成标量）——定义 owner 为 `development/RGCD数学模型.md` §12；`experiment/metrics.py::edge_distance` / `tau_distance` 为其二值实现。

## 3. 实验协议（A–F）

共有前提：使用 §1.1 的 seed 集；每项实验给出 目的 / 自变量 / 因变量 / 预算 / 产物 / 判据。A–F 均为**必做**（对应 `docs/验收清单.md` Research 段）。

### 3.1 Experiment A — Genome → Architecture
- **目的**：刻画「基因组 → 结构统计」的分布。
- **自变量**：随机生成的 **48 个 genome**（与 `configs/evolution.yaml::population_size` 对齐；随机源由 `core` seed manager 派生，禁自建随机源）。
- **处理**：每个 genome 跑**完整发育**（RGCD）。
- **记录**：motif affinity、GRN final states、neuron count、cell-type distribution、edge density、tau distribution。
- **产物**：结构统计表 + 分布图。

### 3.2 Experiment B — Single-base Mutation
- **代表 haplotype**：固定 seed 下 **generation-0 的首个个体**（记录其 `genome_id`）。
- **处理**：对该 haplotype 的 **256 个位点**逐位做 deterministic alternative-base mutation（位点方向定义 owner：`genome/生物学与进化遗传学基础.md` §5）。
- **计算**：\(\Delta Expression = |E - E'| / E\) 的**逐 motif 均值**；`d_edge`、`d_τ`、`ΔB`（引 §2.5）。
- **Genome Sensitivity Map**：横轴 256 个位点，纵轴 Δ 大小，按四位点 / motif 分组聚合的**条形热图**。
- **预算**：256 个位点**全部逐位跑**（每位做完整发育；不降采样）。

### 3.3 Experiment C — Baseline
- **模型**：MLP、GRU、Fixed Sparse RNN、DanioNet；三个 baseline 的实现与尺寸反解见 `connectome/DanioNet设计规范.md` §8（`connectome/baselines.py`，连接数 196 / 200 / 190，均满足判据）。
- **控制**：相同数据；相同训练预算（BC：`K=20` mini-batch，`learning/行为克隆学习.md` §3）；参数量同一数量级（**按连接（权重）数比较**，`|log10 N_base − log10 N_ours| ≤ 1`，`DanioNet设计规范.md` §8）；相同 evaluation episodes（每条件 3 seed × 每 seed 1 个 episode）。**模型评估由 `scripts/run_chain.py`（DanioNet 驱动）执行**；`scripts/run_arena.py`（ExpertPolicy 驱动）只用于环境 pre-check / 基线，**不用于模型评估**（`learning §5`）。
- **指标**：survival、prey capture、escape success、energy efficiency、inference latency、FLOPs、parameter count、active edges。
- **产物**：对比表（含方差与重复次数）。

### 3.4 Experiment D — Ablation

实现口径 owner：`connectome/DanioNet设计规范.md` §9。**选定 3 个消融臂**（对应验收「3 ablations」），均只改一个变量：

| 臂 | 变更（唯一变量） | 运行方式 |

- **τ 网格**（设计选择 **D**，防选值偏袒 `[bib#27][bib#28]`）：`τ* ∈ {τ_min, (τ_min+τ_max)/2, τ_max}`，当前 config 下 = `{1, 5.5, 10}`——**由 `connectome` 段派生**，非外部取值。
- **对照控制（定稿）**：架构臂评估口径同 Experiment C（`scripts/run_chain.py`，DanioNet 驱动）；BC 臂同 `learning §3` 的数据/预算/标准化（`scripts/run_bc.py`）。各臂仅变上表一个变量，同 seed、同 `n`、同 episode 预算。

### 3.5 Experiment E — Robustness

### 3.6 Experiment F — Environmental Selection
相同 initial population 分别进入 §4 的三组环境，运行 `generations` 代（正式取 `configs/experiment.yaml::generations = 20`；执行编排 = `experiment/evolution_run.py::run_evolution`，契约见 `experiment/代循环编排.md`，CLI `scripts/run_evolution.py`），记录：
- allele frequency（**按位点**：512 位点 = 2 条 haplotype × 256）
- phenotype frequency（**四类表型** `A_B_` / `A_bb` / `aaB_` / `aabb` 的个体占比）
- viability、fitness、neuron count、edge count、tau statistics

跨环境比较用原始指标（§2.3）。
**强制 pilot 门（20 代的依据）**：正式跑满代前，先跑 **10 代 pilot**，**同时报告每代 `n_viable` 与瓶颈率**（`evolution.population_bottleneck` 会终止代循环）。**pilot 已实测（2026-09-26，3 seed × 20 代 = 60 代，N=48，基线）**：`n_viable` 逐 seed 稳定为 4.15 / 6.15 / 4.15（min 4、max 7），瓶颈 **0/60**，实测 viability 率 10.0% —— 二项独立假设（≈14%/代）偏保守，N=48 跑满 20 代安全；
**种群规模取舍（2026-09-26 用户裁定）**：正式 E–F 保持 `population_size=48`。因每代仅约 5 个 viable 个体参与选择，报告须声明「选择功效弱、环境效应量仅作指示」，不得据此下强结论。再以「**同环境 seed 间 spread**」作噪声带判断区分力；若环境间差落在噪声带内，不得直接以 20 代结果作「有效应」结论，须延长代数或如实报「当前幅度无区分力」。依据：种群 48、seed 3，漂变强，代数过少时漂变会盖过环境效应；代循环每代评估 **1 个 Arena episode**（`experiment/代循环编排.md` §5：逐代 `episode_id=ep0001`）；按实测 ExpertPolicy 吞吐（12 鱼 × 600 步 ≈ 2 s）粗估，20 代 × 4 条件 × 3 seed ≈ 数十分钟，预算允许。
H2 专门分析：connectome 与行为矩阵的 **Mantel 检验**（`问题定义与研究假设.md` §2 映射表）`[bib#21]`。

### 3.7 Mendelian validation

\[
\chi^2=\sum_i\frac{(O_i-E_i)^2}{E_i}

### 3.8 Experiment BC — 生命周期学习（Stage 1 + Stage 2 + 学习前/后对照）

实现 owner：`experiment/learning_run.py`；薄 CLI `scripts/run_bc.py`。训练契约 owner = `learning §3`；驱动分工 owner = `learning §5`。

- **目的**：给出「同一 DNA 经学习能得到多好的行为」的可验证证据（`learning §1`），并作为 Experiment D「BC 有/无 Dale 符号约束」的载体。
- **链路**：`initial_population → phenotypes_of（全体，记 viability）→ 仅 viable 构造 DanioNet → 训练前同一局评估 → Stage-1 轨迹 → 逐个体 `train_bc` → 训练后同一局评估 → 非遗传证据`。
- **规模**：当代个体数 `n` 默认 12（`ExpertPolicy` pre-check 规模，§4）；轨迹条数 `learning.trajectories`（默认 200，`learning §2`）。
- **对照控制（定稿）**：训练前/后使用**同一批 arena 子种子（`generation`）与同一网络对象**，仅 `Θ` 不同，故指标差可归因于学习；消融臂 `--no-sign-constrained` 只改 `DanioNet §3` 开关，其余（数据、预算、标准化、evaluation episodes）全同。
- **非遗传证据（定稿，承载 `learning §4`）**：训练后**重新发育同一 genome**，新网络 `max|ΔW| < 1e-5`（float32 容差）且 `W⁰` 与训练用网络逐元素相同 ⇒ `ΔW` 只在当代表型、未入遗传通路。
- **产物（布局见 §5.1）**：`metrics.csv`（`phase ∈ {pre, post}`，逐个体）；`learning.jsonl`（逐 viable 个体：`final_loss`/`epochs`/`coverage_steps`/`flip_rate`/`spectral_radius`/`delta_w_norm`/损失权重）；`learning_summary.json`（seed 级学习汇总 + 非遗传证据）；`seed_summary.json` 取 `post` 行跨 seed 汇总。
- **评估入口**：由 `DanioNet` 驱动（`learning §5`），经 `pipeline/arena_episode.py::drive_arena_with_net`（`pipeline §4`）。

## 4. 环境对照三组（owner：本节）

> 取值落 `configs/experiment_environments.yaml`（Tier-5，**值冲突以 configs 为准**），依据与状态落 `docs/参数总表.json`；`environment_id` 由本文件产出（`core/核心机制与数据流.md` §3.1）。
> 状态：**已定稿（2026-09-26 用户裁定采用）**。取值属**设计选择**（无文献实测依据）。

**设计原则：单因子对照。** 每个环境相对基线（`configs/default_arena.yaml`：`n_prey=24`、`n_predators=3`）**只改变一个驱动**，使环境效应可归因。

| 环境 | `environment_id` | `n_prey` | `n_predators` | `prey_regrowth_steps` | 隔离的驱动 |
|---|---|---|---|---|---|
| 基线（非三组之一） | `default` | 24 | 3 | 25 | — |
| Food Rich | `food_rich` | **48** | 3 | **13** | 猎物可得性 ↑ |
| Predator Rich | `predator_rich` | 24 | **6** | 25 | 捕食压力 ↑ |
| Resource Scarce | `resource_scarce` | **12** | 3 | **50** | 猎物可得性 ↓ |

**派生约定（不新增旋钮）**：`prey_regrowth_steps = ceil(600 / n_prey)`（向上取整：不早于名义速率回复；默认 `600/24 = 25`，与 `default_arena.yaml` 一致），故它随 `n_prey` 机械确定。
不用 `round`：`600/48 = 12.5` 是平局，`round` 走银行家舍入得 `12`，语义含混；`ceil` 无歧义。

**未改变的量（必须保持不变，否则对照失效）**：`world`（含 `episode_steps=600`）、`sensing`、`energy`、`growth`（含 `capture_radius`、`κ`、前向锥）、`actors` 全部取默认；`n_fish=12`、`n_obstacles=6` 不变（**本节的 12 鱼是 `ExpertPolicy` pre-check/环境对照的规模**；Experiment F 的演化评估用 48 个体，由 `pipeline/arena_episode.py` 按 viable 数覆盖 `n_fish`，`arena §3`）。实验环境**不得**暗改契约值。

**前置区分力检查（2026-09-26，A14 随机流拆分后重跑；基线对照 `exp_arena_expert_ref_v3`，环境 run `exp_env_*`）**：
> 证据：`results/tables/<run_id>_summary.json`（不入库；`scripts/make_env_compare.py` 可重出）。重跑 `exp_env_*` / `exp_env_*_v2` / `exp_arena_expert_ref_v3` 三套**逐指标数值一致**，构成复现性证据。

> ⚠️ **本轮为 A14 拆分 Arena 随机流（`arena_spawn`/`arena_dynamics`）后的重跑**（run id `exp_env_*`；`scripts/make_env_compare.py` 直接可出图）。
> 旧表（`predator_rich` d=+2.89 等）产生于随机流耦合时期，**已作废**。

| 指标 | 基线 | food_rich | predator_rich | resource_scarce |
|---|---|---|---|---|
| survival | 0.9188 | 0.8847 (d=−0.32) | 0.8258 (d=−0.70) | 0.9431 (d=+0.25) |
| capture_rate（主口径） | 0.00296 | 0.00380 (d=+0.83) | 0.00208 (d=−0.83) | 0.00148 (**d=−1.43**) |
| prey_capture（个体比值均值） | 0.5148 | 0.5162 (d=+0.01) | 0.4667 (d=−0.20) | 0.5612 (d=+0.18) |
| escape_success | 0.3032 | 0.2477 (d=−0.43) | 0.2903 (d=−0.12) | 0.1667 (d=−0.95) |
| energy_efficiency | −0.925e−3 | −0.945e−3 (d=−0.17) | −1.071e−3 (d=−1.25) | −1.138e−3 (**d=−1.79**) |
| composite_fitness | 0.3828 | 0.3599 (d=−0.44) | 0.3474 (d=−0.53) | 0.3635 (d=−0.34) |
| 绝对量：捕获 / episode | 21.3 | **27.3** | 15.0 | **10.7** |
| 绝对量：遭遇 / episode | 266.3 | **591.7** | 145.3 | **30.0** |

（d = (环境 − 基线) / 合并 SD；n=3 ⇒ SD 本身不稳，仅作指示。）

> ✅ **基线已冻结（2026-09-26）**：`exp_arena_expert_ref_v3`（seeds 1103/2207/3301 × 600 步 × 12 鱼，ExpertPolicy）摘要入库 `artifacts/baseline/`（含复现命令与本文件指标的逐位核验）。冻结依据：arena 参数（含原 24 个「标定占位」）按**设计选择（D）**定稿（`docs/参数总表.json` v0.14）；ExpertPolicy 只读 `obs[0..5]`/`obs[11]`，不读 `obs[6..10]`（A5 looming 不影响）。**任何 arena 取值变更即解冻并重跑**。

**结论（均须写进报告，诚实版）**：
1. **本 pre-check 无稳健区分力**：最大 |d| 为 `resource_scarce` 的 `energy_efficiency`（−1.79）与 `capture_rate`（−1.43），**均未达 1.9σ**；`predator_rich` 现无明显效应（`escape_success` d=−0.12）。n=3 且 12 鱼，**功率不足**，不可据本表断言任何环境效应。
2. **绝对量仍有区分、比值仍弱**：`food_rich` 捕获 21.3 → 27.3（+28%）、遭遇 266 → 592；`resource_scarce` 捕获 → 10.7（−50%）、遭遇 → 30。比值 `prey_capture` 的 d 均 <0.2——再次印证「比值被密度同时抬高分子分母而掩盖效应」，E-F 记录项**必须含绝对量**（§3.6）。
3. **与旧表的差异属真实修正**：旧 `predator_rich` 的强 d 值是随机流耦合时期的产物，已随 A14 拆分作废。

**排期建议（更新）**：正式 E-F **必须走 §3.6 的 pilot 门**（48 个体 × 10 代 pilot，以同环境 seed 间 spread 作噪声带）判断区分力；本 12 鱼 / n=3 pre-check 只作**管道可用性**证据，**不得**作为「环境有效应」的依据。
