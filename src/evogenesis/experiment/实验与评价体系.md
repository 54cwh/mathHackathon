## 1. Reproducibility
Demo seed 与 research seeds 分离。

正式结果至少：

\[
n=3
\]

random seeds，报告 mean ± std。

**统计口径（2026-09-26 定，回答 §阅读问题 #1）**：个体指标先在 **seed 内对个体取等权均值** → 该 seed 的一行；再沿 **seed 轴** 报告 mean ± std（样本标准差，n-1；`n < 2` 时 `std` 记 `null`）。逐个体原值全部保留在 `results/runs/<id>/metrics.csv`，任何人都能重算。实现：`experiment/metrics.py::aggregate_by_seed` / `summarise_over_seeds`；正式跑：`scripts/run_arena.py --experiment-id <id>`（每 seed 一个 run 目录，见 §11）。

## 4. Experiment C — Baseline
- MLP
- GRU
- Fixed Sparse RNN
- DanioNet

控制：
- 相同数据
- 相同训练预算
- 参数量同一数量级
- 相同 evaluation episodes

指标：
- survival
- prey capture
- escape success
- energy efficiency
- inference latency
- parameter count
- active edges

指标定义（供 §9 与 fitness 复用；出处 `research/reference/design-basis-metrics.md`）：
- survival = `survival_steps / episode_steps`
- prey capture = `captures / max(encounters, 1)`；**分母 `encounters` 口径（2026-09-26 用户裁定，已实现）**：「**进入 `capture_radius` 的猎物数**」——即尺寸门**之前**、**纯距离**口径的接触计数（`arena` §18.3.2 **S6**），与 `arena.encounters` 事件同源，故恒有 `captures ≤ encounters`。
  **诊断列 `capture_attempts`（并列报告，不进该指标）**：每鱼每步**至多 1 次** —— 猎物 $d < r_{capture}$ **且在猎人前向锥内**并**判定了尺寸口径**，**不论吃到与否**（吃到走 `arena.prey_captured`，太小走 `arena.capture_attempt`）；锥外不计。恒有 `captures ≤ capture_attempts ≤ encounters`，其中 `capture_attempts − captures` = 「进过口但吃不下」的次数。
**为何这样定（2026-09-26 实测驱动，必读）**：当前捕获是**确定性**的（`P_capture_success = 1.0`，占位）且每鱼每步至多一次判定（`arena` §17 **S5**），实测 **36/36 个体 `capture_attempts == captures`**。若以 `capture_attempts` 为分母，该指标只能取 `1.0` / `0.0`，其均值实际含义退化为「**有过至少一次机会的个体占比**」（实测 `0.7778 = 28/36`），**不是吃到成功率**。改用尺寸门之前的 `encounters` 作分母后，指标恢复「**近距接触中真正得手的比例**」这一有变化含义，并在 `P_capture_success < 1`（方案 a）落地后自动继续成立，无需再改公式。
**未来若引入 `P_capture_success < 1`（`arena` §8 待裁决项 a）**：公式不变，指标自动变为标准成功率；`capture_attempts` 继续作为诊断列并列报告。
实现：`arena/env.py`（`encounters` 计数器 + `capture_attempts` 诊断计数器）+ `experiment/metrics.py::prey_capture_rate`；契约见 `arena/Danio_Arena设计与实现说明.md` §8 与 §13 字段表。**`composite_fitness` 随之可算。**
**⚠️ 分母右偏（2026-09-26 实测，必读）**：`encounters` 计的是**猎物进入半径的事件次数**（S6），不是**不同猎物数**。实测（3 seed × 12 鱼）中位数 **2**、最大 **225**、**前 3 位个体占全体 65.7%**—— 少数「蹲守」在猎物集群里的个体会把分母刷到数百而捕获寥寥（实测 225 次接触吃 1 只 ⇒ 该鱼比值 0.0044）。**故引用 `prey_capture` 均值必须并列偏态**（`diagnostics.md` 已自动输出），不得只报均值。「事件 vs 去重」属**待裁决口径**，见文末阅读问题 #13。
- escape success = `escape_successes / max(predator_encounters, 1)`
- energy efficiency = 净能量积累率简化式 \(r_i=(E_i(T_i)-E_{max})/T_i\)（MVP；口径见 `core/核心机制与数据流.md` §10 #12）
- inference latency = 单步前向延迟 p50/p95（warmup 后测得）
- **选择用 \(F\) 不属本节**：本节只定义**原始分量**与逐个体**显示分**（`experiment/metrics.py::composite_fitness`＝四项 rate 直接加权，无代内归一）。用于选择的 \(F\) 由 `evolution/遗传繁殖与演化模型.md` §6 产出（四项先在**代内 viable** 上 min-max 再加权）；两者不可互替。

> H2 需专门分析：connectome 与行为矩阵的 **Mantel 检验**（本表未单列，见 `问题定义与研究假设.md` §2 映射表）`[bib#21]`。

## 11. Run 目录
```text
results/runs/<experiment_id>-s<seed>/   # 每个 seed 一个 run 目录（experiment_id 由调用方给定）
  metadata.json               # run_experiment.py 写
  config_snapshot/
  arena_config_resolved.json  # 实际生效的 ArenaConfig 快照（原始 YAML 会与解析值漂移）
  metrics.csv                 # 逐个体一行：指标 + 原始计数
  population.jsonl            # 逐个体一行：轨迹幅度等，供作图
  episodes.jsonl              # 逐 episode 一行：事件计数 + 吞吐
  seed_summary.json           # 该 seed 的个体等权均值
  seed.txt
  git_commit.txt
  trajectories/               # Stage-1 BC 专家轨迹（每 episode 一 JSONL；格式 owner = core §4.2/§4.5）
  plots/                      # make_figs.py 产出（每 seed 诊断图）

跨 seed 的 mean ± std 落在 `results/tables/<experiment_id>_summary.json`。
Arena 侧驱动与产物写入：`scripts/run_arena.py`（目录布局仍由 `scripts/run_experiment.py` 单独负责）。
```

**Stage-1 BC 采集（定稿）**：由本模块/`scripts` 编排——`scripts/run_arena.py --emit-trajectories` 以 `ExpertPolicy` 驱动 Arena，逐 step 落 `trajectories/episode_*.jsonl`（字段与格式 owner = `core §4.2/§4.5`，`schemas/trajectory.schema.json`）；`learning` 只消费这些文件。

13. **`encounters` 分母右偏 =「事件 vs 去重」未裁决（2026-09-26 实测）**：`encounters` 是**事件**计数（每步每个进入 `r_capture` 的猎物各计一次，S6），不是**不同猎物数**，故长期蹲守的个体会把分母刷到数百。实测中位数 2 / 最大 225 / 前 3 位占 65.7%，使 `prey_capture` 的个体比值呈极端右偏。**三个选项**（未裁决前不得改口径，也不得只报均值）：(a) 维持事件计数（现状，诚实反映「接触机会」，但须并列偏态）；(b) 改为**去重**计数（每鱼对每只猎物至多计一次接触）—— 更接近「猎物数」，但属 `arena` S6 语义变更，须由该契约 owner 改并重跑全部基线；(c) 改为**按分钟/步数归一**（接触数 / `survival_steps`）—— 消除蹲守放大，但不再是「比例」口径。证据：`results/tables/exp_arena_expert_ref_v2/{diagnostics.md,by_fish.csv}`（不入库，可重生成）。
