# 模型链装配（pipeline/）

> **管辖范围**：把已冻结的模块**串成一条可执行链路**的编排（`config → motif 目录 → 初始种群 → q(G) → 发育 → DanioNet → (ω,v)`）。**不拥有**任何算法、数值或契约：参数取值归 `configs/*.yaml`，字段名/类型归 `schemas/` 与各模块文档，机制归 `core`。（层级与归属见 `AGENTS.md`「文档层级与优先级」。）
> 状态：**v1.0 已定稿（冻结 2026-09-26）**。

## 1. 链路

```text
configs/default_model.yaml
  ├─ genome 节      → GenomeLayout        （genome §2）
  ├─ grn/development/connectome 节 → RGCDConfig（RGCD §13）
  └─ network 节     → NetworkReadoutConfig（DanioNet §）

master_seed ─┬─ motif_catalog 命名空间   → motif 目录（genome §6）
             ├─ initial_population 命名空间 → 初始种群基因组（genome §2）
             └─ development 命名空间       → 单个体的 (A,Z,τ,W⁰,M)（RGCD §1–§11）

genome ──q(G)=genome_affinity──► develop ──ConnectomePhenotype──► DanioNet.step(obs) ──► (ω, v)
```

## 2. 入口（`pipeline/`，按文件分列）

| 函数 | 作用 |
|---|---|
| `load_model_chain_config(path=None) → ModelChainConfig` | 读 `default_model.yaml`，分别经 `load_genome_config` / `load_development_config` / `load_network_config` 得三段配置 |
| `initial_population(*, master_seed, experiment_id, n, layout) → tuple[ChainIndividual, ...]` | generation 0 种群：`random_genome` 均匀 i.i.d.（`genome §2`） |
| `motif_catalog(master_seed, layout) → tuple[str, ...]` | 实验级固定 motif 目录（`motif_catalog_for`） |
| `phenotype_of(genome, motifs, *, master_seed, index, config, device) → ConnectomePhenotype` | `q(G) → develop` |
| `phenotypes_of(individuals, motifs, *, master_seed, config, device) → list[...]` | 批量发育，`index` 取个体在种群中的稳定序号 |
| `danionet_of(phenotypes, *, master_seed, config, device) → DanioNet` | 由发育产物构造网络（batch = 个体数） |
| `viable_pairs(individuals, motifs, *, master_seed, config, device)` | 发育并保留 `viable` 个体（`RGCD §7`） |
| `evaluate_population(individuals, *, master_seed, chain, arena_config, steps=None, generation=0, device="cpu") → PopulationEvaluation` | 评估**一整代**：全体发育（记 viability），仅 viable 进 Arena；返回对齐全体的 `phenotypes` + `episode`（`arena_episode.py`） |
| `run_arena_episode(individuals, *, master_seed, chain, arena_config, steps=None, generation=0, device="cpu") → ArenaEpisodeResult` | 单局便捷封装（无 viable 抛错）；内部走 `evaluate_population` |
| `drive_arena_with_net(individuals, net, *, ...) → ArenaEpisodeResult` | 用**给定** `DanioNet` 驱动 Arena（不重新发育）；供 BC 训练前/后在同一 arena 子种子下复用同一网络对象做对照（`experiment §3.8`）；内部委托 `drive_arena_with_ids` |
| `drive_arena_with_ids(*, fish_ids, genome_ids, net, ...) → ArenaEpisodeResult` | 同上的按稳定 ID 形态；`net` 只需满足 `n_neurons` / `step`（DanioNet 或 baseline，`connectome §8`），供 Experiment C 基线（无 genome）驱动 Arena |
| `arena_seeds_for(master_seed, index=0) → (int, int)` | **采集/代循环**用 Arena 两个整数子种子：`(arena_spawn, arena_dynamics)`（`core §3`） |
| `arena_eval_seeds_for(master_seed, index=0) → (int, int)` | **评估**用 Arena 两个整数子种子：`(arena_eval_spawn=15, arena_eval_dynamics=16)`（`core §4.2`）。与 `arena_seeds_for` **刻意解耦** —— 后者与 `collect.episode_seed` 逐字等价，复用会使评估局与训练数据落在同一批环境实例上 |

`PopulationEvaluation`（本模块边界对象，owner 本节）：`phenotypes: tuple[ConnectomePhenotype, ...]`（与输入同序等长，含 non-viable）、`episode: ArenaEpisodeResult | None`（只覆盖 viable，无 viable 为 `None`）、`viable_indices: tuple[int, ...]`。

§2 表中 `viable_pairs` / `evaluate_population` / `run_arena_episode` / `drive_arena_with_net` / `arena_seeds_for` / `ArenaEpisodeResult` / `PopulationEvaluation` 定义在 `pipeline/arena_episode.py`，其余在 `pipeline/model_chain.py`（`pipeline/__init__.py` 统一 re-export）。

## 3. 种子与 ID（唯一来源）

- 随机源一律经 `core/seed.py` 的 `SeedManager`：`motif_catalog=4`、`initial_population=7`、`development=2`、`network_init=5`（`core §3`）；**Arena 的两个整数子种子**由 `arena_seeds_for(master_seed) → (SeedManager.seed("arena_spawn", 0), SeedManager.seed("arena_dynamics", 0))`（id=3 / id=9）派生后传入 `DanioArena(spawn_seed=..., dynamics_seed=...)`（`core §3` 整数种子例外条款），**不把根部 `master_seed` 直接交给 Arena**。**评估**侧另有独立一对（`arena_eval_spawn=15` / `arena_eval_dynamics=16`，见上表 `arena_eval_seeds_for`），由 Experiment C 与 BC 生命周期评估使用。
- `genome_id` 由 `core/ids.py::mint_id(experiment_id, "genome", generation, index)` 铸造（`core §3.1`）；发育实体序号 `t` 由 `core/ids.py::parse_index(genome_id)` **确定性解析**（`phenotypes_of` 即如此），**不使用调用顺序**——故个体序列重排/子集化不改变任一 genome 的发育随机流。
- 数值不在此层：本模块不出现常量参数，全部由传入的 `GenomeLayout` / `RGCDConfig` / `NetworkReadoutConfig` 提供。
- `ChainIndividual`（本模块值对象：`genome_id` / `fish_id` / `genome`）与 `evolution §5.1 Individual`（含 `fitness` / `viable` / `failure_reason`）**不同物**，故用独立名避免同名混淆；二者共享 `core §3.1` 稳定 ID。

## 6. Demo checkpoint 契约（`artifacts/demo/`，已定稿 2026-09-27）

> 目的：冻结可复现的 Demo 资产，供现场 Demo 与路演 Level-2 兜底**直接加载**，免重建/免训练（`docs/路演与答辩.md` 三级兜底；`core §10 #10` 体积预算）。owner = 本节。

**文件**（`artifacts/demo/`）：

- `checkpoint_v1.pt` —— `torch.save` 的 dict（**仅 tensor / 基本类型**，`torch.load(weights_only=True)` 可读）；
- `population.json` —— manifest：`master_seed` / `experiment_id` / `n_fish` / `viable_indices` / `genome_ids`（重建用，不存 genome 本体）。

**`checkpoint_v1.pt` 字段**：

| 键 | 类型 | 语义 |
|---|---|---|
| `format_version` | int | = 1 |
| `created_at` | str | ISO-8601 UTC |
| `git_commit` | str | 生成时 HEAD |
| `master_seed` | int | 固定 `configs/demo_seed.yaml` 的值 |
| `experiment_id` | str | 铸造 `genome_id` / `fish_id` 用（`core §3.1`） |
| `trained` | bool | 是否含 BC 训练 |
| `individuals` | list[dict] | 每个 viable 个体一项，见下 |

`individuals[i]`：`genome_id` / `fish_id`（str）；`phenotype`（dict：`adjacency` / `weights0` / `tau` / `cell_type` / `positions` / `active_mask` / `z` 张量，重建 `DanioNet` 所需）；`trained_theta`（Tensor，BC 训练后的 `Θ`；未训练时 = 初始 `Θ`）；`final_loss` / `delta_w_norm`（float，训练诊断）。

**加载**：`load_demo_checkpoint(path) → DemoCheckpoint`；重建单个体 = 由 `phenotype` 经 `danionet_of` 构造 → 以 `trained_theta` 覆盖 `Θ`（`connectome §3`：`W⁰`/支撑/先验同构，唯 `Θ` 不同）。

**确定性**：整条链由 `master_seed` 决定（`initial_population → phenotypes_of → danionet_of`）；生成命令固定为
`uv run python scripts/freeze_checkpoint.py --out artifacts/demo`（`--no-train` 跳过 BC，仅供快速测试）。

**体积**：单文件 `≤ 50 MiB`、`artifacts/` 总量 `≤ 100 MB`、不用 Git LFS（`core §10 #10`）；48×48 `float32` ≈ 9 KB/网络。

**消费方**：API `POST /v1/sessions` 的 `checkpoint_path`（`model_driven=true` 时优先加载）；路演 Level-2 兜底。实现：格式/加载 = `pipeline/checkpoint.py`（`save/load_demo_checkpoint`、`DemoCheckpoint.build_net`）；**生成**（含采集/BC 训练）= `experiment/freeze_run.py`（消费 `collect` + `learning_run`，保持 `pipeline` 不反向依赖）+ 薄 CLI `scripts/freeze_checkpoint.py`；`tests/test_checkpoint.py` 守护 round-trip。
