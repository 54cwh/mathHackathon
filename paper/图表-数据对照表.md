# 图表 ↔ Excel 数据对照表

> **owner / 属地**：李辰钊（charts + report lane）。
> **用途**：后续统一美化图表时，**改样式不改数据** —— 每张图的底层数据都在同名 `.xlsx` 里。
> **状态**：2026-09-26 建立。

## 1. 命名与存放约定（不可变）

```
<fig_dir>/<fig_name>.png        ← 图
<fig_dir>/data/<fig_name>.xlsx  ← 该图的**全部**底层数据（同文件名）
```

- **同名即对应**：Excel 与图**文件名相同、后缀不同**，只多一层 `data/` 子目录。
  拿到 `fig_metrics_mean_std.png` 就必然有 `data/fig_metrics_mean_std.xlsx`，不需要人工映射表。
- **每个 `.xlsx` 第一个 sheet 固定为 `_manifest`**：逐 sheet 写明
  `figure / caption / shape / columns / source`，外加 provenance（`experiment_id`、`git_commit` 等）。
  不看代码也能知道每张 sheet 是什么、什么口径。
- 其余 sheet **一律原始数据**（列名保持英文原名），美化时只改样式。
- 数据**不入库**（`results/**` 被忽略），但**可由脚本一键重生成**：
  ```bash
  .venv/Scripts/python.exe scripts/run_arena.py --experiment-id <id>   # 生产数据
  .venv/Scripts/python.exe scripts/make_figs.py --experiment-id <id>   # 出图 + 出 Excel
  .venv/Scripts/python.exe scripts/make_tables.py --experiment-id <id> # 出表 + 诊断
  .venv/Scripts/python.exe scripts/make_env_compare.py                 # 环境对照图 + Excel
  .venv/Scripts/python.exe scripts/make_fig_viability.py               # F6 发育 viability 图 + Excel
  .venv/Scripts/python.exe scripts/make_fig_pipeline.py                # F12 数据流总览图 + Excel
  .venv/Scripts/python.exe scripts/dump_connectome_matrix.py           # F7 连接矩阵落盘（48×48 W⁰/支撑/Θ）
  .venv/Scripts/python.exe scripts/make_fig_connectome.py              # F7 连接矩阵图 + Excel（读上面的 JSON）
  ```
- 实现见 `src/evogenesis/viz/figdata.py`；守护测试 `tests/test_figdata.py`。
- 图/表脚本的**入口**须调 `experiment/console.py::force_utf8_stdout()`（被管道重定向时不因中文而崩）。

## 3. ⚠️ 引用数字时必须一并声明的事项

美化时若在图注/标题里写数字，以下各条**必须同时出现**，否则会被误读：

1. **`prey_capture` 有两个口径且差 7 倍**：个体比值均值（0.5407）vs 汇总比值（0.0762 = 55/722）。
   报哪个必须写明（`实验与评价体系.md` §2.1）。
2. **分母右偏**：`encounters` 中位数 2 / 最大 225 / 前 3 位个体占 65.7% —— 均值须并列偏态。
3. **`energy_efficiency` 是非正速率**（≈ −1e−3/step），**不可与 0–1 的 ratio 同轴**（图中已单独分轴）。
4. **F6 发育 viability：正式配置下 100%，八项判据零次触发（2026-09-26 更新）**：
   实测 **1000/1000 = 100%**（Wilson [99.6%, 100.0%]），pipeline `q(G)` 口径 **200/200**。
   成因是判据 (ii) `|h|<1`（解析保证）、判据 (iv) `ρ(W⁰)<1`（初始化重定保证）与
   `missing_fate`（`c_domain` 谱系先验保证）三者均为**设计约定**，恒真而不贡献区分力。
   **旧口径（2/14 = 14.3%、71/1000 = 7.1%）已作废**：那是修复前的读数，其中 92% 的拒绝
   来自失配的 ρ 阈值；解除三处约定可复现「4.7% 通过」，但其可绑定区是致死的逐 seed 彩券。
   **报告不得再写「发育是强约束筛选」**；筛选压力归代际适应度 `F`。
   依据：`research/notes/契约决策记录.md`「§7 发育良构门禁的区分力裁决」。
   口径与复现命令见 `results/figs/dev_viability/data/fig_viability.xlsx` 的 `_manifest`。
5. **F7 有两组极易混的对比，报数时必须分别写明**（`paper/latex/sections/02-method.tex`
   §「48-node 的含义」讲的正是第 (a) 条）：
   - **(a) 容量 48 ≠ 实际 N**：`development.max_neurons = 48` 是张量的**补零容量**
     （`48×48 = 2304` 个元素/个体），不是某个基因型的规模；实测活跃神经元数 **N 中位 36.5（27–43）**，
     张量里 `N..47` 的行列恒 0。写「48 节点网络」时必须同时给出 N 的分布，否则会被读成固定 48。
   - **(b) 支撑 ≠ 全张量 2304**：`Θ` 有 2304 个元素，但只有支撑 `A` 之内才可训练
     （`allow_self_loops = false`，对角恒 0）；实测支撑边 **中位 195（105–289）**，
     即张量元素的 **8.5%**（个体层面 4.6%–12.5%）。2304 是容器容量，195 才是参数量口径。
   两组读数都是「3 个正式 seed × 14 个体 = 42 个基因型」上的，落在
   `results/tables/connectome_matrix.json` 的 `architecture_probe.pooled` 与配套
   `population` sheet；口径与复现命令见 `results/figs/connectome/data/fig_connectome.xlsx` 的 `_manifest`。
