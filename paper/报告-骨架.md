## 0. 写作主轴与判据

赛题补充说明（Tier 0，`docs/赛题补充说明.md`）把评审关注点写死为四问：

> **为什么要改 → 改了什么 → 实际结果如何 → 具有什么价值与意义**

四条硬约束直接决定本报告结构：架构要实际验证（原模型→改后模型→结果对比）；复杂度不等于创新（每个设计选择带理由与代价）；成果要有图与典型案例；产品界面不构成创新。论文篇幅不作为依据，全文压到「最短能讲清四问」，删装饰性章节。

## 2. 去内部痕迹规则（正文与图表硬禁清单）

论文只写**模型与方法**，不写**开发过程**。以下一律不得出现在正文、图表、图注与脚注；确需说明的工程细节只留在仓库文档，不进论文：

| 禁出现 | 例（旧稿） | 论文里改写成 |
|---|---|---|
| 仓库路径 / 文件名 | `scripts/probe_architecture.py`、`results/tables/*.json` | 删除；需要出处就写「本文实验数据」或落到附录 |
| 文档章节号 / 票据号 | `core §2`、`Arena §8 项 a`、`P0-9`、`A14`、`D5`、认领表 A1 | 删除，或改为自然语言（如「随机源按模块拆分」） |
| commit / 哈希 / 摘要 | `commit 82d8dcc`、`sha256`、`digest` | 删除 |
| 版本 / 状态机词汇 | `已定稿`、`草案待确认`、`标定占位`、`守护路径`、`v1.8` | 删除；未定取值改写成「本文取值为设计选择」 |
| 逐位 / 逐字节一致 | `逐字节一致`、`float32/float64 对齐缺口` | 改写成「确定性重放」的数学陈述（若必需） |
| 「没做完」的工程叙述 | `尚未实现`、`未接入流水线`、`未跑通`、`占位` | 只在 §7 与 §8 以「模型局限」的学生语言保留（见 §4） |
| 内部裁决 / 自我更正 | 「旧读数作废」「已撤回」「退役理由」 | 删除；只保留最终采用的口径 |
| 跨 lane / 分工 | 「交接给某位同学」「属模型 lane」 | 删除 |
| 实验记录口吻 | 「第三个 seed 按限时停止」「本稿不含」 | 改写为结果或局限陈述 |
| 运维细节 | `uv.lock` 2750 行、清华源、`PEP695` | 移入附录且只留「锁定依赖可复现」一句 |

写作手法遵守 `docs/ai-tone-boundaries.md`：不用「不是…而是」式翻案腔，正文不用箭头代替因果，非数学的 `+` 不用于拼合。

## 5. 口径与误差（引用结果时必须并列）

三处最易误读，凡引用对应数字必须同时声明；权威口径 owner 为 `experiment/实验与评价体系.md`：

- 三个都叫「捕获率」的量数值差约 7 倍（个体比值均值 / 汇总比值 / 绝对速率），正文一律标明是哪一种；
- `prey_capture` 分母 `encounters` 严重右偏（少数个体主导），引用其均值必须并列偏态尾与绝对量；
- `energy_efficiency` 是每步非正速率，不可与 $[0,1]$ 比值同轴。
